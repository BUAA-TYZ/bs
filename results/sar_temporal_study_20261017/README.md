## 固定条件与方法

除公共中继组件外，源配置与`../sar_dispatch_20261016/main_config.json`完全相同：46星、
16调度块/64推理窗、实测并发组、2 Gbps星间、960 Mbps星地、8跳、0.01秒步长、相同任务与输出真值。
`manifest.json`记录源配置、输入依据及派生哈希；不调整到达率、带宽或评分制造优势。

temporal在公开未来接触上搜索完整包最早交付，允许等待下一次星间窗口；首跳必须当前可执行。
缓存、共享带宽、任务完成、字节和工时仍用原执行器。等待包每秒重规划，实际发送继续逐步推进。
当前缓存状态用于未来节点的保守可行性检查；已知队列影响报价，未知未来竞争不读取。
它没有持久路径承诺或独占预约，不保证预测窗口与后续执行一致。

这是[CGR](https://ntrs.nasa.gov/search.jsp?R=20120006508)/
[SABR](https://ccsds.org/Pubs/734x3b1.pdf)思想的仿真适配，不是本文原创或完整标准实现。
容量、缓存预测与安全余量也已有[相关研究](https://arxiv.org/html/2410.15546v1)，
因此不能把新增保护余量或未来窗口本身包装为创新。当前候选研究整图AND交付下的计算选择。

- CGS：原计算机会适配，逐片选择输入、计算与结果交付机会。
- CGS+余量：规划阶段扣除执行器已有的30秒星间接触尾部保护期。
- CGS+整图门控：对同源剩余兄弟片用实测服务曲线与预计结果总量报价；带扫描余量仍可
  300秒内交付时选本地，否则回退CGS+余量。结果总量当成单包估计，偏保守；实际逐块交付。
  当前摘要无法重建已派发兄弟片的真实尾时刻，因此不是所有历史承诺的完成保证。

## 因果诊断

此前1040秒4图上，旧snapshot路由的CGS为0/4；确定性回放逐任务结果与旧记录一致。
只放宽到16跳为2/4，temporal保留8跳也为2/4，救回集合均为task_0、task_3。
16跳同时进入规划与执行，不能将该反事实解释成只改变末端路由的独立因果效应。
相同temporal给地面后仍为1/4，本地则4/4，说明不能仅通过弱化地面对照声称调度收益。

首图尾片task_0_tile_0：snapshot在568.12秒算完，沿18→20→22→0→24→2→4→25走7跳，
570.05秒到25号星，其北京窗口仍需779.95秒。temporal沿18→38→16→37→14→36→12→27，
等到570秒附近的新接触，570.05秒已完成下行。这个尾片并未耗尽8跳；缺少未来ISL机会是直接证据。
仅加跳数不是普遍修复，尚不能把所有失败都归为同一原因。

完整逐跳事件与早期变体位于`../sar_temporal_probe_20261016/`，其中不同变体研发阶段的源码哈希
不同，只作机制诊断；最终方法横比以本目录同源码面板为准。原始轨迹、前缀配置和哈希均保留。

## 当前瓶颈与后续

1. 规划与执行口径仍不完全一致：CGS只扣接触总量，路由按实际到达重新选首跳；保护余量不等于
   持久执行保证，接单后改路和误过窗口仍会发生。
2. 门控的整图总量单包报价可能过度保守；实际推理、结果产生和中继是流水过程，需要验证
   每个分片产出时刻、剩余跳数、接触关闭及共享接收时间，避免错误回退。
3. 原图一旦承诺地面中继，不能自动恢复星上处理；宜研究有界承诺与失败后的重新选择，
   并给文献对照相同动作能力。不能只给新方法增加独占路由权限。
4. 预测边界按30秒采样、真实几何10秒更新，而处理仅几秒；在切换点附近，数秒误差足以改变
   整图是否完成。需先给出预测误差与决策失误的逐事件证据，再决定更复杂算法或学习是否有价值。

当前没有训练出新MARL模型。新方法保持研究候选身份，论文正文未改。
517项测试通过；六种方法的工时、已完成窗口数、字节和时间戳审计全部通过。
主机上的决策耗时已在summary.json保存，不能当作Jetson上的运行时间。
