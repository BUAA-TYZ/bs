## 固定项

| 项目 | 数值与口径 |
|---|---|
| 场景 | 24颗SAR源星570 km、97.7度，22颗计算中继星550 km、53度；180图开发日、五港口、北京地面站 |
| 原图 | 5x5 km名义幅面，0.25 m像元间距、0.5 m分辨率，20000x20000单通道uint16，800 MB |
| 推理窗口 | 4096x4096，步长2304，通常重叠1792像素/448 m，末窗贴边重叠更大，共64窗 |
| 星载服务 | 源星、计算星相同；单窗0.597 s，双窗并发组1.056 s，不等待凑组；饱和约1.894窗/s |
| 星载内存 | OS可见32.188686336 GB共享池；系统8、执行14、数据缓存10 GB，余量约0.189 GB |
| 地面计算 | 单星饱和吞吐10倍的等效容量，64窗纯服务3.3792 s；不是A100等型号的实测值 |
| 指标 | 图像形成就绪起300 s内全部处理结果到地面并完成聚合；分母含空目标图与超时图 |
| 数值步长 | 0.01 s；调度1 s、几何更新10 s；接触预测采样30 s，需保留收敛检查 |

Jetson的固定服务曲线来自同一网络、精度、输入窗口的三轮及持续测量，是地面硬件代理。
不能推广成所有SAR识别器的耗时，也不能据此声称已有相同性能的抗辐照飞行计算机。
内存是共享内存与逻辑配额，不是独立32 GB显存，也不是三块互不重叠的实测峰值。
测量来源：`../jetson_concurrency_20261016/summary.json`及其README。

## 链路基准

| 项目 | 主档 | 证据性质 |
|---|---|---|
| 星间标称速率 | 2500 Mbps | SCOT80公开档位，非本星座实测 |
| 星间载荷效率 | 0.8 | 工程敏感性假设；不是厂商协议效率 |
| 星间执行容量 | 2000 Mbps/方向/已连接链路 | 标称乘效率，同一方向多流共享；双向独立容量是假设 |
| 同时邻星上限 | 每星2个 | 两端度数均限制，按距离确定性匹配；未实现业务驱动终端切换 |
| 距离截断 | 4500 km | 几何研究约束，仍需地球无遮挡；不是链路预算验证 |
| 星地标称/执行容量 | 1200/960 Mbps | 跨平台成像星公开档位乘0.8；一个接收服务，不是每星独占地面站 |

传输容量在链路接通后固定；几何接触、度数限制和队列竞争使实际可用服务随时间变化。
当前没有足以标定距离自适应码率、随机掉速或抖动的测量，因此不使用正弦/噪声制造“真实性”。
可见不等于立刻捕获成功：当前未计入捕获/重指向时间，传播时延也未进入执行推进；
`latency_ms`字段不应被当作已生效的物理时延模型。4500 km单程传播约15 ms。

SCOT80公开每光学通道11.9 kg、60-80 W。两个同时工作通道仅通信终端约23.8 kg、120-160 W。
本场景必须解释为能承载这些设备的研究平台，不能套称6U立方星或ICEYE实际平台。
目前没有整星SAR成像峰值、计算板功耗、太阳阵、电池与热平衡数据，整星能源可行性仍未认证。
减少带宽不会自动按比例降低终端固定功耗；不用25 Mbps/560 km试验拼接4500 km通信能力。

来源：
- [TESAT SCOT80参数表](https://www.tesat.de/images/tesat/products/250820_DataSheet_SCOT80_A4.pdf)：2.5/10 Gbps、质量与功耗。
- [TESAT Kepler在轨验证](https://www.tesat.de/news/blog/942-kepler-validates-tesat-optical-communication-terminals-in-orbit-for-kepler-network)：LEO星间链路真实验证，未给持续业务吞吐曲线。
- [Airbus Pléiades Neo论文](https://zenodo.org/records/7244968/files/Session%202B-Le_Lann-Image%20Compression%20on%20Pleiades%20Neo.pdf)：1.2 Gbps双通道聚合星地下行，跨平台参考。
- [ICEYE Spot Fine产品规范](https://sar.iceye.com/6.0.8/productspecification/imagingmodes/)：幅面与像元间距依据，不证明本研究平台功率或星间配置。

## 分片变量

推理窗口固定；优先比较不同调度分组，避免改变网络输入与识别质量假设。

| 每组窗口排列 | 调度块数 | 总推理窗口数 | 块内去重后总输入 | 最大调度块 |
|---|---:|---:|---:|---:|
| 1x1 | 64 | 64 | 2147.484 MB | 33.554 MB |
| 2x2 | 16 | 64 | 1287.883 MB | 81.920 MB |
| 4x4 | 4 | 64 | 949.783 MB | 242.352 MB |

16块是重点候选，4块为较粗粒度对照。边缘分组因原推理末窗贴边而略小，不能写成16个等大的6400块。
当前打包器仍累加完整窗口字节，没有块内去重；实测并发执行器只接受每块一个推理窗口。
因此当前可运行主配置仍是64块。16/4块须先接入内部窗口执行、完成计数、缓存释放、结果合并，
再运行比较；本目录不生成会错误套用单窗耗时的大块“可运行配置”。

直接重切4096/5120/6400/8192的几何候选另见`packet_candidates.json`；后三档未标定计算服务。
不能用“片数减少”推导相同比例计算加速。固定推理分组只改变传输、任务分配与调度开销。
链路准入检查应采用排队时间+字节/实际分配速率+余量，不以标称速率或整段窗口总长替代剩余窗口。
现有执行器支持断链保留进度，但路径规划的窗口准入更保守；两者均须在比较时共享。

## 结果语义与剩余边界

业务目标已确定：没有检测到目标时只回小型完成确认；有目标时回元数据和预览，不要求原图同时回传。
未知船型不等于无目标；原图到地面计算的分支仍需上传原始像素；不能预知空目标并免除计算成本。
所有图的全部窗口确认到齐后才算完成。当前可运行配置仍使用每窗0.86857875 MB固定结果代理，
尚未实现空目标分布和变长结果，不能将当前传输量称为该业务的最终真实数据量。
当前到达清单是几何覆盖生成的固定港口重复观测；未模拟沿轨相邻幅面、姿态机动与SAR占空比。

## 已准备的对照

`manifest.json`记录每份配置哈希和来源，旧配置快照不回写。
主档之外只做单因素变更，不自动执行笛卡尔积：

- 星间标称100、600、10000 Mbps，效率仍0.8，即80、480、8000 Mbps执行容量。低速档是敏感性假设，不绑定另一套低功耗设备。
- 星间效率0.6、1.0，即1500、2500 Mbps；星地与邻接不变。
- 星地效率1.0，即1200 Mbps；星间保持2000 Mbps。
- 邻星上限4，作为更高通信资源预算对照；不得沿用两路功率解释。

假设：在同一计算与成像负载下，通信容量和任务粒度影响卸载收益；若无改善或更差则报告负结果。
