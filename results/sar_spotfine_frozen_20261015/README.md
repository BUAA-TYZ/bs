# SAR统一算力主配置

用户确认全部节点采用相同算力后，于2026-10-15固定。入口为`main_config.json`；`manifest.json`保存原始测量摘要、成像轨迹、参数依据、输入哈希与配置哈希。

| 项目 | 主设定 |
| --- | --- |
| 星座 | 24颗SAR源星（570 km、97.7度、12面×2星）+22颗计算中继星（550 km、53度、2面×11星） |
| 任务 | 美国沿海五港参照点，单日180次图像就绪，24/24个UTC小时有任务，最长间隔2685 s |
| 图像 | Spot Fine规格参照，5×5 km、0.5 m分辨率、0.25 m像元间距、20000²单通道uint16、800 MB |
| 分片 | 4096窗、1792重叠、2304步长，末窗贴边，64包，每包33.554432 MB |
| 工作量 | 每窗1 U；所有星与地面节点均1.7421602787456447 U/s、一个串行槽 |
| 输出 | 识别元数据+完整目标ROI的512²单通道uint8预览；平均0.86857875 MB/窗、55.58904 MB/图 |
| 聚合 | 实测0.25091760235 s/图，当前0.1 s步长下生效0.3 s |
| 缓存与执行 | 星上各8 GB逻辑预算，来自约32 GB级共享内存；不重复计物理RAM/显存 |
| 链路 | ISL 10 Gbps、星地聚合1.2 Gbps，北京参考站一个聚合接收服务 |
| 主指标 | 图像形成就绪后300秒内，全部结果及预览在地面完成聚合的任务比例；分母为全部任务 |

图像形成时间采用采集结束后60 s的上游假设；不在本轮识别服务计时内。窗口1792像素重叠覆盖400×61.5 m船体设计包络及每侧16 m上下文，不等于真实SAR标注或识别精度保证。100个合成目标及固定均值结果量是共同负载假设。

原图地面计算路径传输800 MB唯一像素，随后执行同样的64窗；逐窗路径传输总计2147.483648 MB，重复像素不免费。分布式缓存实存窗口，8 GB最多容纳3幅完整未处理图像。收到原图不算完成任务，仍须处理并聚合。完整原图也必须在同一SLA送达的业务对照尚未实现。

统一算力是用户选择的实验控制条件，不代表真实地面服务器的性能。地面端内存准入、共享聚合竞争队列尚未建模；聚合目前仅为固定延迟。链路取不同任务的公开设备量级，理想协议效率和零建链耗时是研究假设，不能称完整复现真实ICEYE星座。

配置反序列化往返、46星与地面统一速率、首次任务64窗/64U/输入与结果字节均验证通过；组件检查跳过与此无关的全天可见性预计算。相关标定、重叠、工作量及计算预算36个单元测试通过。此处未产生调度算法排名。10 Gbps下单窗理论传输仅26.84 ms，dt=0.1 s会量化逐跳完成事件，正式算法结论前须做保持其他物理周期不变的更细步长核查。

复算配置：

```bash
.venv/bin/python analysis/build_sar_frozen_config.py \
  --calibration-report results/sar_spotfine_calibration_20261015/calibration_summary.json \
  --workload-fixture results/sar_spotfine_calibration_20261015/workload_fixture.json \
  --output-dir /tmp/sar_frozen_recomputed
```

生成器要求标定通过、负载文件哈希完全一致，并核验几何、逐窗结果、源星映射和24小时任务覆盖；不会覆盖已有输出目录。
