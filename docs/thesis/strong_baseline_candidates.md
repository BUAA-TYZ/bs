# 强文献对照候选与复现边界

核验日期：2026-10-15。本文档是文献调查和实现建议，没有新增实验结果，也没有改动正在冻结运行的仿真核心。

## 结论

当前可以核清原算法且最接近本课题的三个候选是：资源感知 CGS 的 CGR/MSR 变体、2026 年遥感边缘智能的 `P_sch` 优化、2023 年 SMEC 的 BCD 分配优化。没有找到一个已核验方法同时原生覆盖“变化的星间接触、整图全部分片、五分钟软时限、已接单队列”。不能因此认为本文方法已超过这些论文。

推荐先补 CGS 对照的实现范围验证，并独立复现 `P_sch` 的原模型；SMEC BCD 作为同一研究方向的前序参照，避免把三个名字当成三个完全独立算法家族。HEFT 保留为通用 DAG 对照；DTS-TMAX 一跳适配作为较轻量的局部选择对照。

## 1. CGS 的资源感知与 MSR 变体

一手来源：Lowe et al., *A delay-tolerant network approach to satellite pickup and delivery scheduling*, Ad Hoc Networks 151, 103289, 2023。[机构原文](https://strathprints.strath.ac.uk/86667/7/Lowe_etal_AHN_2023_A_delay_tolerant_network_approach_to_satellite_pickup_and_delivery_scheduling.pdf)；[作者代码](https://github.com/ApSTL/cgs)；[归档 DOI](https://zenodo.org/records/7737582)。

已核验 Algorithm 1、§4.1、§4.2、§5.1 和 Table 1：按采集机会顺序求最早交付路径，用接触容量与请求期限检查可行性。接单后每条路径边扣减 `C.vol -= R.size`；资源承诺跨后续请求保留。`CGS(CGR)` 使用该接单计划但重新路由；`CGS(MSR)` 优先遵循预先指定的交付路径，无法执行时回退 CGR。原问题没有分片计算队列，且存储和能量视作无限。

### 与当前代码的差距

`CGSComputeAdapted` 把计算完成当作产出机会，具有同轮容量扣减，但每次调用重新构造接触计划；实际结果由公共路由器重新选路。它不是原 `CGS(MSR)`，也不完整保持原文跨请求的未来容量承诺。

建议分两层验收：

1. 独立运行作者原模型：固定作者代码版本，先复现小图的 PU/CGR/MSR 行为、容量更新和失联回退。检查其容量单位、首字节时间与完整负载时间，不把实现中疑似量纲错误直接移植。
2. 新增明确命名的持久容量适配：使用稳定接触 ID 和绝对时间保留承诺，接触结束后回收；重复规划不得重复扣费；取消与失败必须释放。需要为承诺中的输入和结果分别建账。
3. 若做 MSR，必须让实际结果执行器读取规划路径，并在路径失效时回退公共路由。只改变目的地选择而不执行路径，不能叫 MSR。

成本：持久容量版本为中等改动，涉及接触标识、承诺生命周期和失败释放测试；MSR 为更高改动，需要公共传输接口与路径回退支持。应在独立分支或完成当前冻结实验后实施。既有方法和新算法均获得相同路径执行能力后，再比较调度差别。

价值：直接检查当前方法的优势是否来自跨轮容量、计划执行一致性等已有机制。原文没有证明 MSR 在任意场景平均时延都更小，不能先假设它一定占优。

## 2. 2026 年遥感边缘智能 P_sch

一手来源：Soret et al., *Edge Intelligence for Satellite-Based Earth Observation: Scheduling Image Acquisition and Processing*。[正式发表 DOI](https://doi.org/10.1002/sat.70082)；[作者全文](https://arxiv.org/html/2604.05937v1)；[PDF](https://arxiv.org/pdf/2604.05937)。正式发表日期为2026-08-24。

已核验 §4.2、式(23)-(33)及 §5.2：比例 `x[s,p]` 将每批图像分配给卫星或地面，频率 `f[p]` 控制处理速度；散发、计算、汇聚分别位于 `k,k+1,k+2` 时隙。目标是处理与通信能耗总和，约束包含全量分配、处理时限、ISL 与下行容量。式(31)消去频率并代入式(32)，配合式(33)得到凸优化。原网络假设固定 ISL，未建模一般突发积压队列。

### 可复现的核心

先实现原文的独立优化器：输入每批工作量、节点处理模型、最短路径、时隙和下行容量，输出 `x` 和 `f`。保留原能耗目标，先做两节点/三节点可穷举小例与 KKT、资源守恒检查，再检验 Fig. 10 的负载可行性趋势。不要先把目标改成时延再宣称复现成功。

式(31)可以用以下等价参数表示，便于防止单位混淆：定义 `n_p = D_s*x[s,p]/D_img`，单图平均处理时间为 `a_p/f_p + b_p`，其中 `a_p = mu_C[p]*W/(cores[p]*FLOPs_per_cycle[p])`。处理约束为

\[
n_p(a_p/f_p+b_p)\leq T_{slot},\qquad
f_p^*=\frac{a_p}{T_{slot}/n_p-b_p}.
\]

`n_p=0` 单独处理；分母非正或 `f_p*>f_max[p]` 为不可行。上述变形仅用于核验原式，不是新算法。

### 接入当前仿真的工作

成本：独立凸优化核心为中等；忠实接入当前时变网络为较高。当前缺少可调频率、能耗模型和多跳原始输入传播；连续比例还必须映射到不可拆的315个实际包。可先在论文原拓扑上验证，再引入显式命名的固定频率适配；不能静默删除能耗、改变结果大小或为该方法预知未产生任务。

优先级高于继续增加随机/贪心变体：它把一批图像的处理和最终汇聚作为整体，能针对本课题的整图尾部问题提供有力参照。

### 参数引用边界

Table 3 和 §5.2提供 Jetson 平台的 YOLOv8 测量/拟合模型。文中 CPU 数值来自相似架构测量后按核心和频率缩放，不能宣传为所列全部型号的直接实测。正文与表格的 Nano 功耗值存在15W/25W差异；引用前必须明确采用哪一版本和工作模式。论文中的均值、端到端时限、三阶段时隙也不能混为一个时间口径。

## 3. 2023 年 SMEC BCD

一手来源：Leyva-Mayorga et al., *Satellite Edge Computing for Real-Time and Very-High Resolution Earth Observation*, IEEE TCOM 71(10):6180-6194, 2023。[DOI](https://doi.org/10.1109/TCOMM.2023.3296584)；[作者 PDF](https://arxiv.org/pdf/2212.12912)。

已核验 §III、式(18)-(28)、Algorithm 1：联合优化分配量 `X`、压缩率 `rho`、处理频率 `F`，使散发、计算、汇聚能耗最小；所有分段数据必须守恒。处理和通信资源按任务周期切片，约束平均工作量不超过周期容量。路径使用既定最少跳路由。先用式(27)求最小可行频率，再以 BCD 交替优化分配和压缩；作者使用 CVXPY/MOSEK。

### 复现建议

成本：原优化模型中等偏高，包含分块下降、增广拉格朗日/IPDD细节和压缩率对应的计算模型；接入当前仿真更高，因为还需真实压缩/能耗参数及多跳散发。未确认作者公开代码，不能将第三方同名实现视为作者实现。

更可控的顺序是先复现其 JPEG 固定复杂度特例，再验证一般指数复杂度下的 BCD 单调下降、约束残差和终止容差；最后才与当前任务比较。该方法的实时性是资源稳定性和周期约束，不能直接解释成每幅突发影像五分钟内完整交付。当前固定压缩、固定算力、无能耗的实验若采用类似分配优化，只能叫受启发的适配，不是完整 SMEC BCD。

## 4. 补充：DCoflow 与 Varys 的整任务调度先例

### 4.1 DCoflow 的可复现核心

原文把同一任务的多个并行传输流作为一个 coflow，完成时间是所有流完成时间的最大值，目标为期限内完成的 coflow 数量。网络是固定容量的非阻塞 Big-Switch；每条流同时占用一个入口和一个出口。它没有计算节点选择、CPU 服务、输入与输出的先后依赖，也没有预测卫星接触。

令 `p[l,k]` 为 coflow `k` 在端口 `l` 上的总剩余字节数除以该端口速率，`T[k]` 为剩余期限，`S` 为尚未排序的任务。Algorithm 1 从队尾反向构造顺序：选择总工作量最大的端口 `b`，在使用该端口且 `sum(p[b,j], j in S) <= T[k]` 的候选中，把期限最大的任务安排到当前队尾。如果没有这样的候选，`DCoflow_v1` 暂时排除在瓶颈端口上使下式最小的任务：

\[
\Psi_{l,k}=p_{l,k}\left(T_k-\sum_{j\in S}p_{l,j}\right),\qquad
k^*=\arg\min_{k:p_{b,k}>0}\sum_{l:\Psi_{l,k}<0}\Psi_{l,k}.
\]

随后按照得到的顺序重新估计完成时间，检查暂排除任务；只有仍会迟到的任务才从本轮接纳序列中移除。`v2` 改为对接近瓶颈负荷的端口求和，因此还需一个拥塞阈值；优先复现不需要该阈值的 `v1`，避免为当前实验另行调参。这里是文献选择理由，不是已证实 `v1` 在本场景最强。

原文 Algorithm 1 第11行把最大期限的候选集合印成全体 `C`，与紧随其后的解释不一致。作者在线代码明确限定于瓶颈端口上的可行集合，应以解释和代码交叉核验，不能照抄该行造成重复选入已移除任务。作者在线实现还将重新估计后迟到的全部任务纳入清理，而纸面伪代码显式跟踪暂排除集合；原模型复现必须固定所采用版本并记录这个差别。

作者代码的 `evalCCTfromOrder` 按各端口的前缀工作量估计完成时间；这不等于在耦合入口/出口上的实际完成时间。论文明确承认最终接纳结果仍可能出现期限违约。实际传输采用符合 coflow 顺序的 `GreedyFlowScheduling`：优先流取得其路径端口的可用带宽，互不冲突的流可并行。仅生成排序但继续对全部活动流等分带宽，不是这一执行机制。

### 4.2 拒绝、终止与迟到继续的精确区别

| 情况 | 原文/作者实现的行为 | 本项目适配需要说明的变化 |
| --- | --- | --- |
| 离线 `RemoveLateCoflows` 拒绝 | 从本次接纳序列移除，不再为其安排该计划的服务 | 不能把移除任务从全体到达任务分母中删除 |
| 在线、期限未到 | 论文明确允许下一轮重新考虑先前拒绝者，并使用剩余流量；作者在线实现将预测拒绝者追加到接纳序列之后，仍可利用资源 | 可以对应“暂缓尚未承诺的尾部分片”，但已有排队/传输工作不能被撤销 |
| 在线、期限已到 | 作者期限模式停止剩余传输、记入拒绝集合，退出活动任务集 | 与300秒软 SLA 后继续完成不同；不能直接采用该终止行为 |
| 本项目迟到继续 | 是需要额外定义的统一运行规则 | 应明确命名为 `late-continue` 适配，对所有方法使用相同规则并报告最终完成率与迟到积压 |

上述代码核验固定于 `luuquangtrung/CoflowSimulator` 的提交 `6153478ed0788d1fac1455f4c3cf893a1aff08f3`，MIT 许可证。关键位置为 `matlab/release/+CoflowOrderAlgos/+DeadlineAwareAlgos/dcoflow_online.m`、`matlab/release/+utils/evalCCTfromOrder.m`、`matlab/release/online_config/online_simulator/onlineCoflowSimulator.m` 的 `computePriorities` 与 `applyAllocation`、以及 `online_config/allocators/greedyAllocator.m`。其中 `computePriorities` 的输出是 `[outputs.order outputs.pred_rejects]`，到期终止由 `is_dl_aware` 控制。不能只看 `pred_rejects` 字段就断言任务已被丢弃。

公开仓库有离线、在线和旧版本；离线代码中存在重复除以端口容量的表达式，而在线版先把需求转成秒后不再重复除容量。原论文实验的归一化容量为1，会掩盖这种差异。因此不能直接复制离线代码到 Mbps 不同的卫星链路，必须先用不等容量小例核验量纲。仓库中的 `python/README.md` 为空，当前应将公开可读实现记为 MATLAB，不能声称已有可直接使用的 Python 原版。

### 4.3 Varys 的两个模式不能混用

Varys 也以整组流的最后完成时刻为完成时间。其平均完成时间模式按 `SEBF` 的有效瓶颈时间排序，再以 `MADD` 分配各流速率。给定剩余端口容量 `Rem` 和流量矩阵 `d`，瓶颈时间为：

\[
\Gamma_k=\max\left\{\max_i\frac{\sum_j d^{(k)}_{ij}}{Rem_i^{in}},
\max_j\frac{\sum_i d^{(k)}_{ij}}{Rem_j^{out}}\right\}.
\]

`MADD` 使用 `r[i,j]=d[i,j]/Gamma[k]`，让同任务各流以瓶颈完成时间为目标，并将剩余容量分给后续任务；还需补充工作守恒与防止饥饿的机制。

论文 §5.4 的期限模式不是简单的 `SEBF + EDF`。它先以剩余流量除以剩余期限，重新保留已接纳任务的最低带宽；新任务只有在剩余容量下 `Gamma[k] <= T[k]` 时才进入，接纳后不被新任务抢占其保障。§3.2 明确被拒绝的请求需以后重新提交，未规定我们的自动迟到继续队列。这个模式更适合检验“保护已接单任务”机制；平均时延模式则是另一条对照，不能用两者中有利的部分拼成未说明的新算法。

### 4.4 当前动作空间下可以做什么

| 原算法需要 | 当前仿真的现实 | 对照应如何命名/处理 |
| --- | --- | --- |
| 同一 coflow 的流集合与大小已知 | 可知道已到达整图及其所有未承诺兄弟片 | 必须包含全部剩余分片；不能只用候选截断后的少量片估计整图尾部，也不能读取未来尚未到达图像 |
| 固定端点和固定端口容量 | 计算目的地待选、星间/星地接触有起止时间 | 端点选择与接触预测是适配层；不能直接把窗口容量当常数带宽使用 |
| 并行网络流 | 输入、CPU、结果之间存在先后依赖 | 把三阶段工作量都放进 `p` 仅是资源负载投影，不保留原可行性性质；需公共执行预测器检查阶段顺序和接触截止 |
| 在线重排、可抢占流带宽 | 只有 `LOCAL/OFFLOAD/WAIT`，公共 `fair_bytes` 传输与已承诺 FIFO CPU | 排序只能控制新接单；不能重排正在执行或已接受的工作，也不能实现原带宽保障 |
| 期限后终止或拒绝未接纳请求 | 软 SLA 超时后仍要求尽量完成 | 统一保留迟到队列；`late-continue` 必须写进适配名称与协议 |

因此，冻结核心内可以研究 `DCoflow-v1 task-order adapted (late-continue)`，但它是整图接单排序对照，不是原 `DCoflow` 的完整复现。建议先固定同一个公共分片落点/路径估计器，给所有任务级对照同样的候选信息、已有承诺和接触预测；只比较 DCoflow 排序、Varys 式瓶颈排序以及本文排序/接单规则。已有承诺作为不可撤销的背景负载扣除，待排序对象限于可决策尾部；不能让 DCoflow 假定自己能回收已承诺资源。结果中继也继续由相同执行器完成。

若把 CPU 秒数和各接触的传输需求构造为资源向量，必须把它明示为新的投影适配：接触的发生时刻、任务释放时刻和阶段依赖无法由一个端口负载标量完整表达。不能用投影后的并行不等式宣称300秒内必定完成，也不能将一幅图的输入、CPU 和结果假装同时就绪。尤其当未来接触发生在300秒之后，工作量很小也不构成期限可行。

在 `late-continue` 规则下，不能通过永远不调度迟到任务来隐性实现硬丢弃。可使用公共、预先固定的迟到服务规则，并同时检查它对及时任务的资源影响；仅在“当前没有及时任务”时运行迟到队列，在持续负载下仍可能使其永久饥饿。若当前接口无法保证两类服务资源，应如实报告该限制，不能声称具备 Varys 的防饥饿或带宽保证。

### 4.5 推荐落实顺序和验收

1. **优先补文献定位。** 将 coflow 作为整图任务级优化的直接先例；“整图感知”本身不再单列为原创算法贡献。可检验的增量是未来接触与执行约束下的承诺控制和尾部完工判断。
2. **独立复现原核。** 用固定 Big-Switch、无 CPU 的小模型移植 DCoflow-v1；先验证论文 Fig.1/Table II 示例、非单位端口容量、相同期限、在线已传流量扣除、预拒绝重新进入和到期终止。比较原代码与纸面差异，固定版本。该步骤成本中等，算法不依赖 MILP 求解器；公开代码存在不等于实验已经复现。
3. **再做统一场景适配。** 只控制当前可提交的任务尾部，保留相同公共分配器和 `late-continue` 规则；针对失联、迟到、部分兄弟片已在途以及候选截断做资源守恒检查。成本中等，但结论只针对适配版。
4. **需要强完成保证时再改公共执行层。** 要复现 DCoflow 的优先级流服务或 Varys 的最低带宽保障，须增加调度可控的速率/优先级接口、抢占边界与跨轮承诺，并为所有比较方法开放。时变接触、CPU 与依赖关系仍需要另外处理，成本较高，不宜在当前冻结实验中修改。
5. **分开报告目标。** 原 coflow 期限实验报告期限内整任务数量；本项目报告所有到达图像为分母的 P300、300秒截断时延、最终完成率及迟到积压。原网络结果、卫星适配结果和本文算法结果不可混写成“超过原论文最强方法”。
