# 计算与回传容量预约调度

更新：2026-10-10。用户指出多个成像源可能同时选择同一个计算/回传窗口较好的节点，并允许在 MARL 增益不足时，以专门调度策略作为方法主线。本轮实现可执行的调度层预约原型，首先隔离“预测”与“同轮竞争协调”的贡献。

后续已完成退化路径审计与整图滚动预检：八场景评分 73.9720% → 74.1218%，完整交付仍为 753/754。新增四项测试后全套 116 项通过；搜索宽度扩大没有评分增益，接触边界与回传路径估计仍是瓶颈。详见 [整图接纳实验](joint_admission.md)。下文保留首版实验协议与结果。

## 问题与现有缺口

接收内存不是完全没有保护：`DistributedPipeline._offload_to_sat` 在接受原始分片时立即占用目的节点内存；但容量不足会使分片失败，且没有计算时间或回传窗口的接单约束。旧 greedy/window_aware 从同一时刻的队列快照独立选择多个分片，前一个选择不更新后续选择看到的工作量，因此同轮请求可以集中到同一目的节点。正在传向该节点的原始分片也没有体现在其本地队列长度中。

新策略关注三个阶段是否衔接：原始数据传到目的节点，已承诺工作之后完成计算，结果再经可用窗口抵达地面。计算节点不必自己直接下传，首版估计允许直接回传或经当前邻星进行一跳结果中继；实际环境仍使用各方法共有的多跳结果路由。

## 已实现内容

- `sim/env.py` 导出各节点的已承诺计算秒数、对应结果量、待路由结果量，以及地面已承诺计算量。包括正在执行、READY 和仍在传入的原始分片；尚未安置的 QUEUED 不计入接单工作量。这些为当前状态广播，未读取未来任务和未来调度结果。
- `sim/scheduler/reservation.py` 提供连续服务时间日历，分别估计有向星间链路、地面站接收通道和每星一个星地终端的占用。计算按仿真时间步向上取整，候选下传必须在预测窗口结束前完成。
- 请求按等待时间、任务 ID、分片 ID 顺序处理。同任务候选连续处理，但不是完整图像的原子接单：公共候选接口仍每星每轮最多四个分片。
- `reservation` 在选定候选后立即更新本轮内存、计算可用时刻及传输日历；后续请求重算目标，找不到可行候选时等待，并在下一轮从真实状态重新尝试。失败兄弟分片的任务不再消耗新增计算。
- `reservation_independent` 使用完全相同的估计、输入和排序，但不提交本轮新增预约，作为协调机制消融。两者后续轨迹不同，真实已承诺负载会随之不同。
- 如果本星、候选计算星及其邻居都没有预测窗口，则退回原 greedy 继续处理，避免把两小时预测时域之外误判为永远不可达。此回退不保证窗口可行，预约版仍检查同轮接收内存。回退次数单独统计。
- 下一轮重新读取真实 READY、RUNNING、传入和下传状态，不保留独立的跨轮租约。完成/失败后工作量自然释放，未来日历也随当前状态重算。

## 实现边界

这是同步共享账本的调度原型，不是真实分布式请求/ACK/租约协议。当前仲裁顺序可看到同一轮全部候选，并使用全体节点的负载广播和地面通道日历，信息多于现有 actor 输入。与无预约版的消融可以隔离本轮协调；与旧 MARL/greedy 的差异则同时包含新增输入和估计，不能全部归为协调贡献。

预约不强制环境按所估路径或时间片执行。共同中继、实际带宽变化、公平传输和站点选择可能偏离估计，不能声称已保证按时回传。当前只检查正在连接的星间接触和最近星地窗口，结果路径估计至多一跳，未实现跨多个未来接触的完整时间展开路径。

已有传输使用剩余字节估计，已承诺计算按串行服务保守累加；仍在传入的任务被纳入工作量，但没有精确复原未来到达顺序。连续字节日历与离散步长执行存在误差，缓存只对原始数据接收作本轮预留，结果缓存没有完整的跨时段预留。无窗口回退、保守等待与拒绝的效果必须通过实际任务结果检验。

信令带宽、广播过期、请求丢失、并发 ACK、租约超时、远程取消和重试成本尚未建模。完整工程协议需在机制收益明确后补充，不把当前理想仲裁描述为已部署能力。

## 验证与复现

全套 112 项测试通过。新增七项测试覆盖：服务日历的空隙与通道、同轮多源改选、窗口满后等待与下一轮释放、不同计算星竞争同一地面站、接收内存与传入计算负载、失败后承诺释放，以及真实流水线中的完整任务收益。

构造的四星机制案例有两个成像源、两个计算目的地，第一颗计算星拥有较短回传窗口。无预约策略将两个任务都送到第一颗，八步内只交付一个；预约策略分流到两个目的节点，交付两个。该例未开启结果中继，用于隔离接单竞争，不代表实际轨道场景或主面板效果。

开发评估固定原八案例、754 个任务、全部公共物理规则和候选数量。比较 greedy、window_aware、reservation_independent、reservation，共 32 次完整六小时轨迹；预测时域、任务源、轨道和带宽不因方法改变。主评分仍为 30/60/120/240 分钟完整交付率的等权平均。结果目录为 `results/relay_reservation_20261010/`，每例立即保存，结束时核对源码、任务、轨道和配置指纹并汇总。

```bash
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python analysis/evaluate_reservation.py \
  --workers 3 --out-dir results/relay_reservation_reproduced
```

也可通过 `main.py --policy reservation` 或 `evaluate_policies.py --policies reservation,reservation_independent,...` 运行。`scheduler_diagnostics` 记录的是请求尝试次数，等待同一个分片多轮会重复计数，不等于独立任务或独立样本数。

## 开发结果

32 次运行全部完成，三个工作进程合计墙钟约 344 秒。全部方法共享源码指纹 `3d8f825aaffe67e217e3f79408595dfb9f4e6a59473f28057a3d1b15b7adbd07`；按场景核对任务轨迹、轨道和配置一致。重新运行的 greedy/window_aware 逐任务结果与 `results/relay_age_baselines_20261010.json` 中归档完全相同，支持新增广播字段未改变这两个旧策略的执行结果。

| 方法 | 多时限交付评分 | 六小时完整交付 | 四小时限制平均时延 / 秒 |
|---|---:|---:|---:|
| greedy | 68.9032% | 741/754 | 3874.8 |
| window_aware | 66.8002% | 741/754 | 4125.9 |
| 同预测、无本轮预约 | 73.0845% | 753/754 | 3324.0 |
| 同预测、启用本轮预约 | 73.9720% | 753/754 | 3176.3 |

预约策略整体相对 greedy 提升 5.0688 个百分点，新增完整交付 12 个任务，没有丢失 greedy 已完成的任务。在共同完成任务中，164 个更快、136 个更慢，不能声称逐任务都改善。

控制相同预测和输入后，预约贡献为平均 0.8875 个百分点，限制平均时延减少 147.6 秒，最终完整交付总数没有增加。大部分相对旧基线的评分增益已出现在无预约版本，来自新增工作量信息、端到端估计与等待/选择规则这一整体；当前实验尚未进一步分解这些因素。

预约相对无预约在 6/8 个场景改善，在两个均匀布局场景退化；相对 greedy 则为 5/8 改善。整体相对 greedy 的增益主要受均匀布局的两个场景影响，而预约的正增益发生在邻近与共享布局。该异质性要求进一步解释竞争强度与估计误差，不能根据案例名称事后挑选开关再报告同一面板为测试结果。

这是既有开发面板的一轮确定性策略比较，未更改轨道和工作负载来挑有利场景，但面板本身已多次使用。因此不能当成新的独立测试或领域最优结论；也没有在本轮重新训练/评估同信息权限的 MARL。历史 BC 的 69.2520% 可作为开发背景，不能将当前策略收益称为学习增益。

## 与现有研究的关系

预约、接纳控制和轨道感知本身不能直接称为新创新，已找到两个需要进一步对照的来源：

- Magliarisi、Casalicchio、Salvatore，2025，*Orbit-aware task scheduling in satellite edge computing*：研究轨道运动、资源和时限约束下的分布式卸载与资源分配。其任务来自地面用户，未处理本文的图像分片全完成与共同结果中继语义。[原论文](https://link.springer.com/article/10.1007/s10586-025-05663-9)
- Lowe 等，2023，*A delay-tolerant network approach to satellite pickup and delivery scheduling*：Contact Graph Scheduling 将任务分配与数据交付路径结合，适用于时变、间歇连接网络。它是联合调度与路由的相关基线候选，不能把本文原型冠以该方法名称。[原论文](https://www.sciencedirect.com/science/article/pii/S1570870523002093)

本轮完成的是来源核对和方法边界初筛，未完成两篇方法的复现。后续需写清原文公式、实现映射、任务来源、返回结果和资源权限的差异。潜在研究重点是完整图像约束下的计算/回传联合接纳、多源竞争协调与窗口失效恢复，是否构成贡献取决于与已有方法的差异及实验证据。

## 后续顺序

先判断预约相对相同估计的独立决策是否改善完整任务，再检查收益/退化案例的路径和时延。若主要收益来自回传估计，应如实把预测作为主要改进；若预约过于保守，应改估计和仲裁目标，不能取消公共竞争规则。下一阶段优先补完整任务的联合接纳与更准确的未来接触路径，然后验证过期广播和协商开销。

MARL 可继续作为对照，或学习候选排序/报价中的难估部分，但必须与相同预约机制和相同信息的非学习版本对照。论文不再以“必须训出一个胜出的 MARL”为完成条件。
