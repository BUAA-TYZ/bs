# 遥感输入、分片与输出规模：证据核验与标定建议

核验日期：2026-10-14。范围为输入字节、分片、输出语义和仿真映射。官方产品元数据支持的算术示例，与本轮DOTA P0007/P0019实测分开记录；已完成YOLO11n-OBB同机CPU/MPS小样本测量，未测星载或服务器硬件，未统计完整数据集分布。

`image_tiling` 已接入执行器，当前固定1024窗口、824步长、200名义重叠，实际推理、OBB1编码及全图NMS结果见[固定重叠协议](fixed_overlap_protocol.md)。128 MB、8片与0.5 MB仍指D1/D2/C1的抽象机制工作负载，不能用新增测量追认其来源。

## 1. 核心判断

历史抽象配置`examples/config_relay.yaml`的`image_size_mb: 128`没有已记录的真实图像或模型测量依据，应继续称为抽象开发参数。它不是明显不可能的规模，但不能因为后来能构造出相近的影像，就倒推为原参数的实测来源。尤其需要区分`128 MB = 128,000,000 B`与`128 MiB = 134,217,728 B = 134.217728 MB`。

遥感图像没有通用的“每张多少 MB”。大小取决于空间范围、地面采样距离、波段、存储类型、处理级别、压缩和有效像素比例。另一方面，传输一幅图像所需的字节数、模型在内存中的张量大小、一次模型推理的 patch 大小和一个完整任务的输入量可以完全不同。论文必须分别定义。

抽象协议每片固定返回`0.5 MB`同样不是遥感任务的一般事实。检测框、类别掩膜和校正后影像的返回规模可相差数个数量级。仅在明确输出语义与序列化格式后，才可以讨论星上计算对下传量的节省。

## 3. 字节、位和张量的可复算口径

本文约定 `1 MB = 10^6 B`、`1 MiB = 2^20 B`、`1 Mb = 10^6 bit`，`1 B = 8 bit`。对于已解码、字节对齐、无行填充的数组：

```text
B_array = sum_b(H_b * W_b * bytes_per_sample_b)
MB = B_array / 1,000,000
MiB = B_array / 1,048,576
Mb = 8 * B_array / 1,000,000
T_payload_seconds = 8 * B_wire / (R_Mbps * 1,000,000)
```

`B_array` 不含容器头、地理定位、质量层和协议开销。`B_wire` 必须按实际传输形式取值：原压缩文件、重新压缩的分片或未压缩数组并不相等。若明确按位打包 12 bit 数据，应另算 `ceil(H*W*12/8)`；这不是 uint16 产品数组的算法。float32 模型输入每样本占 4 B，但网络激活、权重及工作区还会继续占用显存。

| 算术例子 | 字节 B | 十进制 MB | 二进制 MiB | 十进制 Mb |
|---|---:|---:|---:|---:|
| 4000 × 4000 × 3，uint8 RGB | 48,000,000 | 48 | 45.776367 | 384 |
| 1024 × 1024 × 3，uint8 RGB patch | 3,145,728 | 3.145728 | 3 | 25.165824 |
| 4096 × 4096 × 4，uint16 | 134,217,728 | 134.217728 | 128 | 1073.741824 |
| 1024 × 1024 × 4，uint16 patch | 8,388,608 | 8.388608 | 8 | 67.108864 |
| 10980 × 10980 × 4，uint16，S2 四个 10 m 波段的典型完整网格 | 964,483,200 | 964.4832 | 919.802856 | 7715.8656 |
| S2 L1C 13 个波段各保留原生网格，uint16 | 1,346,257,800 | 1346.2578 | 1283.891487 | 10770.0624 |

最后一行按 `2 * (4*10980^2 + 6*5490^2 + 3*1830^2)` 推导，是光谱数组量，不是整个 SAFE 文件大小。不得把它直接用于 L2A，也不得把 13 个波段全部默认为 10 m 后仍使用此结果。若统一重采样，必须重算。

仅作量纲检查：在持续可用且独占的 20 Mbps 有效载荷链路上，48 MB、134.217728 MB、964.4832 MB 分别需 19.2 s、53.6870912 s、385.79328 s。此处没有接触等待、排队、竞争、协议或重传，不能称为完整任务的交付时延，也不能据此预判调度优劣。

## 5. 分片不能只做字节均分

对于单轴长度 `W`、窗口边长 `P`、名义重叠 `O`，当前采用末窗贴边且不padding：

```text
reject                            (W < P; padding not modeled)
N_axis = 1                         (W == P)
N_axis = 1 + ceil((W-P)/(P-O))     (W > P, 0 <= O < P)
N_patches = N_width * N_height
```

以4000² RGB为例，stride=1024仍因末窗贴边而有边缘重叠：16个完整窗口共50.331648 MB，原图48 MB。stride=512时贴边生成49窗，共154.140672 MB，重复倍数3.211264；固定主协议stride=824则25窗、78.6432 MB。这里没有补零，三者都只是明确边缘规则的算术。

重复区域是否增加星间传输还取决于实现：在源星切片并发送独立 patch 会重复传输；整块区域只发送一次、在计算星本地裁剪则可能复用已缓存像素，但计算仍可能重复，并引入缓存位置和分组约束。必须选定一种数据流，不应在收益分析中同时取两种方案最有利的部分。

产品 tile、存储 chunk、调度作业和模型 patch 应分别命名。模型输入尺寸由网络和质量要求决定；调度作业可以组合多个 patch，以降低调度和序列化开销。对象跨边界时检测需要坐标还原与重复框处理，分割需要边界融合；几何校正可能依赖 halo、DEM 和轨姿辅助数据。不能默认任意图像处理都可分为相互独立、计算量相同的 8 个作业，也不能把汇聚恒设为一个与数据量无关的真实处理时间。

## 6. 结果大小按语义建模

| 输出类型 | 一个明确表示方式的算术例子 | 对历史0.5 MB/片的含义 |
|---|---|---|
| 目标检测列表 | 已实现OBB1每目标为8个float32角点坐标、1个float32置信度、1个uint32类别，共40 B，另有28 B消息头；100/1000条仅是4000/40000 B记录的算术示例 | 这是本研究序列化协议，不是DOTA官方文件大小。实测记录数见归档；0.5 MB不是通用值，1000条假设也不是样本统计 |
| 类别分割掩膜 | 1024² 的 uint8 类别图为 1,048,576 B = 1 MiB = 1.048576 MB；二值掩膜若按位打包为 131,072 B = 0.125 MiB = 0.131072 MB | 0.5 MB 不对应这两种未压缩标准表示；若声称来自 PNG/RLE 压缩，须测量真实序列化字节分布 |
| 每类概率图/中间特征 | 1024²、7 类、float32 概率张量为 29,360,128 B = 28 MiB = 29.360128 MB | 不可把概率图当作一字节类别图；跨星拆神经网络层时中间特征也不能用最终结果量替代 |
| 校正、重采样或重建影像 | 保持 1024²、4 波段、uint16 时为 8 MiB；若输出维度或类型改变，逐项重算 | 结果可能与输入同量级，不能预设星上计算必然减少下传 |

完整任务成功的定义必须对应同一结果质量：各方法返回相同覆盖范围、相同输出语义，并满足统一质量门限。不能让地面基线返回整图、星上方法只返回部分检测框，然后把两者当作同一任务比较。

## 8. 可直接纳入论文的表述

> 遥感任务的数据规模由影像覆盖范围、空间采样、波段组合、存储类型与压缩方式共同确定。本文区分完整影像任务、产品地理 tile、调度作业及模型输入 patch，分别统计实际传输字节和解码后数组量。以 Sentinel-2 四个 10 m 波段为元数据依据，选取 4096 × 4096 像素、16 bit 整数的区域输入时，其未压缩光谱数组为 134,217,728 B，即 128 MiB 或 134.217728 MB。该数值是依据明确维度和表示方式的推导，不能作为已有 128 MB 开发设置的历史实测依据。[SentiWiki](https://sentiwiki.copernicus.eu/web/s2-mission)

> 图像分片同时影响模型质量、计算量和通信量。DOTA原论文采用1024×1024像素及512像素步长执行检测，表明模型patch可以包含重叠区域；本轮固定的是1024窗口、824步长与末窗贴边，并未复用原论文的512步长。已对两张真实原图完成像素裁剪、逐窗推理、坐标恢复、OBB1序列化与全图NMS。源星独立发送完整窗口，重叠像素重复计入输入传输；相邻2×2窗口组成调度包。该具体实现已建立窗口、作业和服务量的对应，但200像素重叠仍是固定控制，不是质量最优证明。[DOTA原论文§5.2](https://openaccess.thecvf.com/content_cvpr_2018/papers/Xia_DOTA_A_Large-Scale_CVPR_2018_paper.pdf)

> 返回结果的大小由任务语义决定。目标检测一般交付数量可变的目标记录，语义分割交付覆盖指定区域的类别图，影像校正则可能仍需交付与输入同维度的多波段栅格。历史固定输入、成本和结果大小用于抽象机制开发；当前检测代理已经记录两图实际字节和同机CPU/MPS服务时间，仿真按模板平均每窗值派生各包开销。两图、每后端三次重复和固定阈值质量诊断仍不足以代表完整数据集或目标设备，不能由测量完成推出特定星载平台的端到端性能保证。
