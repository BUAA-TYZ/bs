# 整图交付候选及适用边界

日期：2026-10-15。实现为 [TaskDeliveryPolicy](../../sim/scheduler/task_delivery.py)，验证见 [专项测试](../../tests/test_task_delivery.py)。这是在线规则候选，不是新训练的强化学习模型，也不是原文献算法的完整复现。正式场景是否优于文献适配，必须以同版本、同能力的配对实验判断。

## 1. 优化对象

每轮只考虑公共 `decision_state` 当前可动作前缀中的任务，以及这些任务在 `pending_task_tiles` 中已释放、未承诺的全部兄弟分片。它不读取未到达任务，也不意味着同时优化系统内所有已释放任务：尚未进入当前动作前缀的另一幅图不在本轮整图集合中。

对固定的本轮任务集合，先最大化预测完整图像在 SLA 内交付的数量，再最小化各图像截断交付时延之和。正式 SLA 为 300 秒，构造参数可调整。未能为全部剩余兄弟找到方案的图像记为预测未完成；不能用部分片完成代替整图完成。集合固定时，这与先比较该集合的 P300、再比较 R300 等价，但不是对未知未来到达的全局最优保证。

同图已有承诺的预计尾部与全部待规划分片的交付时刻取最大值，再计入图像已等待时间和公共后处理延迟。已有承诺尾部来自本策略过去发出动作的报价，不是仿真器未来状态或保证完成时刻。

## 2. 有限候选与实际动作

最多比较三种方案：

1. 逐片 FCFS 参考方案，依等待时间和分片 ID 排序。
2. 按剩余 SLA 排整图顺序，逐图试排全部剩余分片。
3. 按当前可选处理节点数、剩余片数和剩余 SLA 排整图顺序。节点数取该图首个待规划分片的报价数，是轻量启发式；不是整图资源瓶颈的精确求解。

后两种方案中，一幅图试排后若不能整体按时交付，则回滚该图的影子资源占用，先试其他图；之后仍用剩余资源处理被延期的图，不执行丢弃或撤销既有承诺。两个整图顺序相同时只计算一次；只有一个可动作任务时复用 FCFS。`max_orders=1` 是共享其余模型的逐片消融。

候选只有在预测目标严格更优时才替换 FCFS。每个分片保留自己的身份、处理节点和路径，不把其他分片的预约数移植给当前分片。实际动作仍只发给本轮公共额度内的原分片；隐藏兄弟的分配是每轮重算的影子方案。

## 3. 共同资源及预测精度

输入使用所有方法共用的路径候选。卫星计算输入受当前可见路径和共同跳数约束；原始数据地面中继使用共同地面候选和固定最终地面站动作。输入字节、处理服务、缓存和结果接触量均计入同一影子账本，实际由公共执行器收发完整字节并推进计算。

该账本使用累计接触容量和处理节点的预计服务尾部，并非精确重放每个流的公平带宽分配、未来缓存释放和 CPU 到达次序。接触图结果路径也可能与公共逐首跳执行路由不同。预测成功只用于方案选择，论文不能将其称为资源保证、完整时空最优调度或保证满足期限。

相比逐片 CGS 计算机会适配，本候选新增的是整图试排、失败回滚和有限方案比较，不是新增通信能力。相比原影子配额方法，它保留具体分片与落点对应关系，按整图最后交付时间评分。任务级共同完成的目标与 coflow 前人研究有关，不能将“把整幅图一起考虑”本身宣称为首次创新；相关边界见 [强对照调查](strong_baseline_candidates.md)。

## 4. 执行一致性约束

### 决策周期

默认读取公开 `state.config["decision_interval_seconds"]`，环境导出值为 `decision_interval_steps * dt`。旧测试夹具缺少该字段时回退到 1 秒；显式构造参数可覆盖它。隐藏兄弟按照每源后续批次额度分配最早派发时间，而不是假设本轮全部派发。正式面板的积分步长为 0.1 秒、决策周期为 1 秒，两者不能混为一谈。

### 本地 FIFO

`LOCAL` 动作只把分片标为 READY，不改变原有 `sat.queue` 顺序。为避免把不可执行重排记作改进，同一源星上的跨任务 LOCAL 顺序若违反公开 FIFO 顺序，该候选会被拒绝，记录 `rejected_local_fifo_order`；不会修改执行器队列。

真实反例为同一源星的旧图两片、新图一片。修正前候选把新图排在前面，预测新图 2 秒、旧图 4 秒，截断时延和为 6；实际本地 FIFO 为旧图 3 秒、新图 4 秒，和为 7。修正后保留 FCFS，报价与这个无竞争例的实际队列一致。此限制是保守拒绝规则，并不证明所有输入到达、隐藏后缀和执行排队误差均已消除。

### 旧承诺尾部

若公开进度满足 `total == done + failed + 全部未承诺 pending 分片数`，说明同图其余分片全部已处于终态，此时清除旧尾部报价，记录 `cleared_completed_tail`。回归反例中，旧片先前报价为 311 秒，但现已 DONE，剩余片可在图像释放后的 13 秒交付；修正后不再被 311 秒旧报价压住。仍有在途片时不会这样清除。

公开状态仍不提供每个在途兄弟的完整剩余路线，因此仍在途的旧片报价可能偏高或偏低，发出的动作也可能因执行时资源检查未被接纳。该估计不是实际完成时刻的下界。

### READY 与后续额度

正式面板启用 `execution_commitment=True`，READY 已承诺片从公共动作视图排除。未启用该模式时，READY 可能连续占据候选额度；影子规划按后续每轮完整额度推进就可能过于乐观。当前方案没有完整模拟这一非承诺模式，也没有模拟未知未来任务占用额度；不能把正式面板结论直接推广到任意执行模式。

## 5. 已验证的机制与未验证的结论

| 检查 | 实际结果 | 能说明什么 |
|---|---|---|
| 两幅同大小图，FCFS 分片顺序交错，窗口容量只够两片 | FCFS 两幅都不完整；整图方案完成一幅；dt 为 1、0.1、0.05 秒均成立 | 整图接纳能避免容量分散；不是正式高分面板收益 |
| 生成器原始连续任务 ID，旧图三片、新图两片，同窗口只够两片 | FCFS 完成旧图 2/3 片、没有完整图；整图回滚后完成新图 | 不依赖跨任务 ID 交错；这是异构图大小或剩余工作微例，不是每图 315 片同质主场景 |
| 远端 CPU 可执行重排且整图完成数相同 | 预测截断时延和从 9 降到 8 | 检查次目标和真实分片映射；不能替代正式面板执行结果 |
| 公共额度、隐藏兄弟、未来任务、输入/结果容量、缓存、软 SLA 与硬取消 | 专项回归通过 | 检查权限和资源边界，不构成整体优越性证明 |

正式比较应保留 `task_delivery` 与 `task_delivery_fcfs` 消融、共同地面中继能力和相同任务序列，并报告运行成本、失败任务以及差异发生的具体场景。当前已完成的微例不能支持“已超越现有论文方法”的结论。
