# 面向不同星座与工作负载的 MARL 训练

更新：2026-10-08。此前两个训练 episode 只验证运行流程，不能据此判断 MARL 能力；三个固定验证场景也不能代表充分的训练覆盖。现已将训练入口扩展为按分布生成场景，每个 episode 使用新的组合，而非循环几个固定案例。

2026-10-09 补充：本文保留 v1 全星可产生任务的历史开发协议。最新专用成像/计算角色、12/24/36 星训练及 48 星保留案例见 [角色训练记录](role_training.md)，对应 `examples/scenario_roles.json` 的 v2 schema。两个协议不可混合汇总。训练入口现已支持 optimizer/RNG 精确续训；下文关于尚不支持的表述仅描述首次 v1 实验时的状态。

## 1. 当前训练分布

配置为 `examples/scenario_distribution.json`，基础物理规则沿用 `examples/config_training.yaml`。

| 维度 | 当前训练设置 | 采样方式 |
|---|---|---|
| 卫星数量 / 轨道面 | 12 星 = 3×4；24 星 = 3×8；48 星 = 6×8 | 每 3 轮随机排列并各覆盖一次 |
| 轨道高度 | 500–650 km | 连续均匀采样 |
| 倾角 | 45–70° | 连续均匀采样 |
| 升交点赤经整体偏移 | 0–360° | 连续均匀采样 |
| 平近点角整体偏移 | 0–360° | 连续均匀采样 |
| 轨道起始时刻偏移 | 0–6 小时 | 连续均匀采样，每轮仿真 2 小时 |
| 全星座任务到达强度 | 0.002–0.012 task/s | 连续均匀采样，换算为每步 Poisson 均值 |
| 每片计算工作量 | 3–18 | 连续均匀采样 |
| 星间带宽倍率 | 基础配置的 0.5–1.5 倍 | 上下限与噪声同步缩放 |
| 地面带宽倍率 | 基础配置的 0.5–1.5 倍 | 每个站统一缩放 |

这些是第一版开发分布，不是已经从实际任务统计中拟合出的分布。连续采样提供新的组合，但不保证每个组合都有足够交付机会或都适合学习；仍需分层检查覆盖、完成率与学习曲线。稀疏星座中缺少可用 ISL 的情况也可能出现，不按候选策略是否获胜来过滤。

当前到达率是全星座总强度，卫星越多时平均每星负载可能越低。正式规模敏感性实验应分别控制“相同总负载”和“相同每星负载”，不能把规模与负载的混合变化全部解释为规模泛化。

## 2. 怎样生成卫星位置

使用合成 Walker Delta 布局：不同轨道面均匀分布升交点，相同轨道面内均匀分布卫星，并设置面间相位偏移。高度、倾角、整体赤经和相位按分布变化。通过已安装 SGP4 的 `sgp4init` 与 `export_tle` 生成轨道记录，后续仍由原有 Skyfield/SGP4 推进轨道和几何可见性。

这些记录明确标为合成星座，不能称为真实卫星的观测 TLE。使用固定参考历元、近圆偏心率 0.0001、WGS72 引力常数，未模拟轨道维护和长期阻力。原有 24 星 TLE 文件和旧实验均保留，可继续作为独立场景对照。

所有训练条件由训练种子与 episode 编号确定，独立于 PyTorch minibatch 顺序和验证调用。训练日志记录采样参数及配置哈希；run.json 与 checkpoint 保存完整分布定义和哈希。更改分布应使用新的实验目录，不能将其与原运行混合。

## 3. 不同规模如何共用一个模型

actor 仍以每星局部观测为输入，参数由所有卫星共享。候选分片数为 4、邻星槽为 8，地面站数量与顺序仍固定，因此 actor 输入维度不随卫星总数变化。执行时不需要集中 critic，可对更多或更少卫星调用同一 actor；这只是结构兼容，不证明性能能泛化。

MAPPO 集中 critic 按训练分布的最大规模补零。当前最大规模为 48 星，增强特征为每星 169 维，critic 输入为 `(48+1)×169`。小规模 episode 只为真实 agent 创建训练行，缺失卫星只在集中上下文中补零，不产生假 agent 的奖励或动作。bootstrap、奖励和终止张量均使用当前 episode 的实际卫星数。

此实现仍是有训练规模上限的拼接 critic，不是规模无关的图价值网络，也没有获得卫星编号置换不变性。超过 48 星的继续训练需要调整训练容量并建立新模型；只运行 actor 推理不受这个 critic 上限限制。

IPPO 的单星 critic 不需要补零。Co-MAPPO 适配的注意力 Q 按当前 episode 联合 token 数构造输入；不混合不同规模的 episode 到同一 rollout。正式多规模 Co-MAPPO 训练效果仍需单独验证。

## 4. 训练、验证与测试划分

训练起始偏移在 0–6 小时，考虑 2 小时仿真后覆盖到第 8 小时。验证起点分别为第 10、13、16 小时，测试起点从第 24 小时开始；加载配置时检查整个仿真区间不跨集合重叠，而不是只检查开始时刻不同。任务随机种子也检查隔离。

验证固定三个开发条件，覆盖 12、24、48 星及轻载、中等、受限资源；固定它们是为了稳定比较训练进度。不能因为模型某次验证较差就重新随机验证集。三个案例仍较少，正式选模前需要冻结一个更广、每类有多个任务种子且减少因素混杂的验证面板。

测试包含独立轨道时刻和布局，以及 36、60 星未见规模的压力案例。36 星同时提高负载，60 星同时降低带宽，因此这两个案例是组合分布变化，不能单独估计纯粹的规模效应。正式论文需增加单因素控制。当前只保存其配置，未运行测试性能。

即使时间段不重叠，周期轨道也可能产生相似几何状态；不同时间段本身不证明统计独立。这里同时变化布局、相位和任务轨迹，并明确区分范围内新组合与范围外压力条件。

## 5. 训练预算与日志

当前先运行一个训练种子、12 个新场景，三个规模各 4 次，每次 720 步，共 8640 环境步。每 6 轮在固定验证面板选模，保留初始化、最佳与最后模型。它是第一批开发训练，不能称为充分训练或收敛实验。

本批保持此前任务奖励、gamma=1、lambda=0.95、rollout=128、hidden=64 和零势函数系数，先观察改变训练分布后的行为；没有同时修改奖励来人为鼓励卸载。日志新增有效动作计数、活跃 agent 的策略熵、逐轮场景参数与逐验证案例指标。不同大小星座下团队奖励仍按实际 agent 数缩放，评估以场景完成率为主；这与跨场景直接优化平均完成率不是严格等价，后续应检查目标对齐。

训练预算应依据以下信号逐步增加：各类场景是否均得到足够样本；多个独立种子验证曲线是否稳定；是否仍不断获得训练收益；训练与验证差距是否扩大；确定性策略是否只选择本地、等待或无效往返。不要以固定两轮、十二轮或任意一个整数自动宣布算法优劣。

下一阶段可先按 120–300 个 episode 制定开发预算，再根据曲线决定是否继续；这只是预算建议，尚未执行这些长训练。若要精确中断恢复，当前训练入口还需保存 optimizer 和 RNG 状态；现有 `run_marl_study --resume` 只复用已经完成的整次训练，不能接着半次训练更新。

## 6. 运行方式

从仓库根目录运行。以下长训练命令是下一阶段入口，不代表已经执行：

```bash
.venv/bin/python train_marl.py --config examples/config_training.yaml --scenario-distribution examples/scenario_distribution.json --out-dir checkpoints/domain_randomized_120 --algorithm mappo --features task_window --encoder task_attention --reward-mode task --gamma 1 --episodes 120 --eval-every 10 --hidden 64 --rollout-steps 128 --seed 7
```

验证集上的 local 与 checkpoint 对照：

```bash
.venv/bin/python evaluate_policies.py --config examples/config_training.yaml --scenario-distribution examples/scenario_distribution.json --split validation --policies local,window_aware --checkpoint candidate=checkpoints/domain_randomized_120/best.pt --output results/domain_randomized_120_validation.json
```

多种子入口 `run_marl_study.py` 同样支持 `--scenario-distribution`，各方法在相同训练种子与 episode 上看到相同采样配置。该入口会运行预留测试，仅在分布、算法和超参数冻结后使用。默认没有分布参数时仍兼容原固定配置流程。

## 7. 当前验证范围

46 项回归测试通过，新增检查覆盖采样可复现性、每轮规模覆盖、完整时间区间隔离、轨道校验和与传播、卫星位置非重复、变规模 actor/critic 输入，以及批量入口按分布传参和评估配置。批量入口测试使用替身验证调度，不运行预留测试性能。实际 12 轮长轨迹训练及两次验证已完成，未发生维度错误或非有限损失。SGP4 实际版本为 2.25。

尚未完成：充分训练、多独立训练种子、范围外性能验证、规模与负载的控制实验，以及更大验证面板。当前选择合理的低轨参数区间用于开发，并不将其视为最终论文参数依据。

## 8. 第一批开发训练结果

产物：`checkpoints/domain_randomized_development/`，包含完整分布快照、逐轮场景参数、动作与熵统计、初始/最佳/最后 checkpoint；初始模型和 local 对照为 `results/domain_randomized_initial_validation.json`。12 轮训练覆盖 12 个不同配置，12/24/48 星各 4 轮，合计 708 个训练任务，随机采样策略完成 50 个。训练日志记录的训练与选模总耗时约 596.75 秒，不含单独的 initial/local 对照。

| 固定验证面板 | local | 初始化确定性策略 | 第 6 轮 | 第 12 轮 |
|---|---:|---:|---:|---:|
| 12 星 / 21 个任务 | 5 | 0 | 0 | 0 |
| 24 星 / 31 个任务 | 12 | 1 | 0 | 0 |
| 48 星 / 68 个任务 | 27 | 0 | 0 | 0 |
| 合计完成任务 | 44/120 | 1/120 | 0/120 | 0/120 |
| 场景完成率均值 | 34.08% | 1.08% | 0% | 0% |

这些运行的逐案例任务轨迹哈希一致。两次验证均为零，第 6 轮是第一个验证 checkpoint，因此保留为 best；last 为第 12 轮。best 不表示其超过初始化或基线，初始化目前不参与 best 选择。

第 6 轮确定性策略在验证集主要选择等待和卸载，没有选择本地；第 12 轮三个案例的有效决策全部为 WAIT，分别为 22368、30624、75156 次。次数包含同一分片被反复选择，不是分片数。训练随机采样仍有本地计算与任务完成，说明训练采样和确定性执行之间存在明显差异。

这组负结果应保留，不能解释为“增加场景没有用”，也不能解释为已训练到收敛。当前只改变了训练分布和规模兼容方式，保留原稀疏完整任务奖励及较短信用传播配置；仍需更充分预算和受控训练改进。下一阶段优先补齐可恢复训练，再比较较长 rollout、lambda、已有势函数及探索配置；各方法需要同样的训练分布和调参机会。未运行 36/60 星等预留测试性能。
