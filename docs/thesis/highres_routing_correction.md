# 高分辨率场景共享路由修正记录

记录日期：2026-10-15。本记录保存一次已确认的仿真路由错误及其修复依据。以下实验数值全部来自修复前源码，只能用于解释错误，不能作为修复后算法性能或论文优越性的证据。修复后正式实验由单独的冻结源码重跑，本记录不提前推断结果。

## 问题与适用范围

共享函数 [`sim/routing.py::delivery_route`](../../sim/routing.py) 为原始分片中继、结果中继估计下一跳。旧实现先对当前有向链路图运行无约束 Dijkstra，每个目的节点只保留一条最短时延路径，然后过滤跳数超过剩余预算或累计传输时间超过接触截止时间的路径。

这种顺序不正确：被保留的最短路径可能不满足约束，但同一目的节点仍有稍慢、跳数更少或接触时间可行的路径。过滤唯一保留路径后，旧实现会错误地认定该目的节点不可达。在 Gbps 链路和较细时间步长下，链路排队与向上取整改变路径排序，使该错误暴露；不是细时间步长本身使真实系统恶化。

影响范围是依赖该共享函数的路由选择及相应比较。旧高分辨率实验中的相对排名不能继续用于正式结论；包括未直接调用该函数的方法，也应在同一修复版本和同一实验清单下重跑，保证比较来源一致。

## 可复核的具体反例

证据见 [160 秒诊断前缀](../../results/highres_routing_diagnostic_20261015/highres_dt01_20261015_until160s.json) 的 `routes`，筛选 `tile_id == "task_1_tile_293"`、`source == 12`：

- 仿真时刻为 **152.7 s**。分片已走过 `[1, 22, 21, 20, 12]`，总跳数预算为 8，**剩余 4 跳**。
- 旧无约束 Dijkstra 为 9 号星保存 `[12, 2, 3, 4, 5, 6, 7, 8, 9]`，共 **8 跳**，随后因剩余预算不足将其删除。
- 同一时刻有可行路径 **`[12, 11, 10, 9]`，共 3 跳**。三条边的估计时延依次为 0.6、0.1、0.2 s；从 152.7 s 起的接触截止时间依次为 3057.3、177.3、7137.3 s。累计到达时间为 0.6、0.7、0.9 s，均满足接触约束。
- 9 号星与北京站正处于可见窗口，剩余 **147.3 s**。因此不能因那条 8 跳路径超预算而将 9 号星整体排除。
- 旧路由实际选择 `[12, 2, 3, 4, 5]`，预计地面交付时刻为 **2070.1 s**；这会在 5 号星耗尽跳数预算，等待后续站窗。
- 前一跳的 152.0 s，旧估计还是 `[20, 12, 11, 10, 9]`，预计交付时刻 **153.8 s**。在下一节点重新求无约束最短路时，可行的少跳路径被丢弃。

该反例无需假设未知未来拥塞，也不依赖性能排名。诊断 JSON 同时保存该时刻完整图的边权、接触截止时间、全部地面窗口和旧无约束路径，可以直接复查。

## 修复方式

新增 `_bounded_paths`，将搜索状态从单一节点扩为 **`(节点, 已用跳数)`**。对每个状态保留最早到达标签，并且：

1. 先从总预算扣除已经实际使用的跳数；只扩展剩余预算以内的状态。
2. 扩展边时检查 `ready_delay + 累计到达时间 <= 接触截止时间`，不可行路径不进入下一层。
3. 对各个可行节点和跳数标签分别估计地面交付完成时间，再沿用 `(finish, len(path), satellite_id, ground_station_id)` 排序。
4. 保留已有的历史访问节点排除、接收内存限制、链路排队估计、传输步长取整和逐步执行检查。
5. 已耗尽星间跳数的节点仍可直接下行；当前不在站窗时仍等待，不产生不合法星间跳转。

此修改修正的是现有模型内的有约束路径搜索，不引入全局未来拥塞信息、不改变分片几何、不改变带宽、不保证实际后续拥塞不变。搜索仍只输出当前首跳，真实传输由仿真逐步推进。固定每边时延且只设截止时间的图中，同一节点、同一跳数的更早到达可支配更晚到达；分层标签避免将“更快但跳数过多”错误地用于支配“稍慢但可行”。

## 回归验证

新增 [`tests/test_bounded_routing.py`](../../tests/test_bounded_routing.py) 共 6 个测试：

1. 快速 8 跳路径不能掩盖可行 3 跳路径；预算放宽后仍可选择快速路径。
2. 累计接触截止时间不满足的最短路径不能掩盖另一条可行路径。
3. `ready_delay` 必须计入各条边的累计接触约束。
4. 已消耗跳数和历史访问节点限制同时生效。
5. 已耗尽星间跳数时仍可从源节点直接下行；未到窗口时等待。
6. 同一地面窗口导致交付时间相同时，按已有规则优先更少跳数。

执行命令：

```sh
PYTHONPATH=tests .venv/bin/python -m unittest test_bounded_routing test_result_relay test_literature_baselines test_compute_service_planners test_overlap_planners test_forecast_reservation test_simulation -v
```

结果：**63 个测试通过**，其中本次新增 6 个、既有相关测试 57 个。检查覆盖结果中继、文献基线、计算服务估计、overlap、预约预测和基本仿真行为。测试通过只支持修复符合上述约束语义，不能替代正式实验或时间步长收敛分析。

## 复现与数据边界

旧诊断由 [`analysis/diagnose_highres_routing.py`](../../analysis/diagnose_highres_routing.py) 生成。该脚本在进程内对返回值插入只读观察；控制周期干预通过进程内 wrapper 完成。诊断提前终止时间分别为 440.0、2066.3、1567.2 s，160 s 文件仅为定位错误的前缀。它们不能用于比较完整观察期的任务年龄分布、固定观察期完成率或后续负载。
