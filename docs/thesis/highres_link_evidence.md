# 高分遥感场景的通信参数依据

核查日期：2026-10-15。本文为“少量高分遥感源星、计算中继星座、中国接收站”候选场景提供参数证据。它不声称复现某个已建成星座，也不把产品规格当成端到端实测吞吐。实际运行参数和实验结果以对应配置及报告为准。

## 1. 取值结论

主档采用星间光链路标称速率 **10,000 Mbps**、星地 X 波段总下行速率 **1,200 Mbps**。前者来自 TESAT SCOT80 官方参数表，后者来自 Airbus 研制人员关于 Pléiades Neo 的技术论文。二者来自不同系统，组合起来构成有公开设备依据的研究场景，并非一套真实星座的完整设备清单。

| 档位 | 星间光链路标称速率 | 星地总下行标称速率 | 用途与依据 |
| --- | ---: | ---: | --- |
| 主档 | 10,000 Mbps | 1,200 Mbps | SCOT80 高速通道档与 Pléiades Neo 双通道 X 波段下行 |
| 较低设备档 | 2,500 Mbps | 900 Mbps | SCOT80 同系列低速通道档与吉林一号高分03D公开最大数传码速率；跨型号技术组合 |

若两类速率同时改变，只能解释为整套通信能力差异。需要归因时，采用 `ISL={2500,10000} Mbps` 与 `downlink={900,1200} Mbps` 的交叉对照，或只改变一项。较低设备档不能因算法更容易获益而替代主档。

主档另设净载荷效率 `eta=1.0` 与 `eta=0.8` 对照：业务容量为 `R_payload=eta*R_nominal`。`eta=1.0` 是没有额外传输开销的理想化上限；`eta=0.8` 是明确标注的敏感性假设，不是厂商公布的协议效率，不是严谨的最坏情况界。不能把 8 Gbps 或 960 Mbps 描述为本系统已测的稳定净吞吐。

## 3. 从设备参数到仿真参数

### 3.1 通道、终端与地面接收资源

一条光链路需要两端相容的终端和指向条件。将星座约束为每星最多4个同时连接的邻星，是**研究中的终端数量假设**。它不由SCOT80的速率规格自动推出。若按4个独立光学通道核算，仅终端就约47.6 kg，标称通信功耗合计约240-320 W；必须避免把这组配置描述成小型43 kg高分03D本体的实际搭载方案。

“双向”允许建立两个传输方向，但目前公开参数表不足以完整确认任意发送/接收组合的内部争用语义。仿真中的独立有向边预算或全双工预算属于明确的执行模型；对端口总吞吐、内部交换总线、缓存争用未建模时应披露。

Pléiades Neo的两路X波段在本研究中抽象为一个**1.2 Gbps聚合下传服务**。若配置字段 `receive_channels=1`，表示接收站同一时刻接入一颗星的该聚合服务，不表示真实射频只有一条载波。每站同时服务几颗星还依赖跟踪天线、接收机和频谱安排，不能由卫星端双通道规格推出。

目前采用一座中国境内仿真接收站并设上述接收预算，是站点和服务配额假设。它不是北京、乌鲁木齐等真实接收站的公开验收值。

### 3.2 距离、可见性和有效速率

星间几何条件至少包括地球遮挡、距离和度数限制。4,500 km可以作为小于8,000 km终端产品范围的**研究距离截断**，但不是从官方参数表推导出的硬件极限，也不保证边缘距离链路一定闭合。轨道高度约620 km时，即使终端宣称可达8,000 km，地球遮挡仍会先限制同高LEO的直接连通。

产品标称速率并不支持人为假定任何一个连续距离衰减函数。此前的 `clip(70+50*sin(...),20,120)/(1+d/2000)` Mbps 是受控抽象容量，并没有天线增益、发射功率、接收灵敏度、编码调制、误码率或天气数据校准，因此不能因为加入距离项就称为真实信道。

本轮使用“满足几何条件后按选定通道速率服务”的分段常数模型更便于追溯。它依然是网络层抽象，缺少链路预算和自适应编码调制曲线；不模拟天气、捕获失败、姿态冲突等因素时，不得宣称复现了完整无线物理层。

### 3.3 建链与时间离散

ESA关于EDRS的[激光通信介绍](https://www.esa.int/Applications/Connectivity_and_Secure_Communications/EDRS/Laser_communications)报告LEO-GEO建链约55秒，但不能直接移植到SCOT80的LEO-LEO链路。零建链开销可用于初步上限实验，真实捕获时间尚待匹配具体终端或作为单独参数研究。

在10 Gbps下，16 MB十进制调度包的纯序列化时间约0.0128秒；在1.2 Gbps下约0.1067秒。若对每包或每跳强制向上取整到1秒，可能使结果主要反映数值离散误差。实验应披露dt、检查同一步是否可复用剩余容量，并对关键比较进行更细时间步长或等价流体服务检查。此算例不含建链、排队和传播。

## 4. 压缩与图像传输体积

[Airbus CORECI2官方参数表，2022-03，第2页](https://www.airbus.com/sites/g/files/jlcbta136/files/2022-05/DS_Payload_Datahandling-CoReCi-2-2022.pdf)公开压缩比范围为3至大于6，并给出4-12 Tb用户存储容量。因而可以把 **3:1** 选为公开范围低端的压缩工况，6:1作为敏感性点。两点都是设备范围内的研究选值，不是已测具体条带的压缩率，也不保证图像质量相同。

Airbus的OBPDC论文第3-5页补充了与建模相关的事实：各光谱波段独立压缩，压缩输出随场景内容变化；内部14 bit采样先舍入到12 bit再压缩。论文未给一个可通用于所有Pléiades Neo影像的固定压缩后bits/pixel。地面交付JPEG2000产品的3.5或8 bits/pixel等设置不能替代星上CORECI2传输码流设置。

对14 km×20 km条带、0.3 m全色与1.2 m六波段多光谱，按12 bit紧凑打包并忽略边界取整计算：

```text
PAN pixels = (14000 / 0.3) * (20000 / 0.3)
MS samples = (14000 / 1.2) * (20000 / 1.2) * 6
raw bytes = (PAN pixels + MS samples) * 12 / 8
          = 6,416,666,666.67 bytes
wire bytes at 3:1 = 2,138,888,888.89 bytes
wire bytes at 6:1 = 1,069,444,444.44 bytes
```

几何尺寸和波段来自[Airbus Pléiades Neo技术表](https://storage.googleapis.com/p-ssp-iep-prod-8ff-strapi-uploads/2025_02_Technical_Sheet_Pleiades_Neo_1_90e5b81067/2025_02_Technical_Sheet_Pleiades_Neo_1_90e5b81067.pdf)，20 km条带长度由研究选定。上述数据量是数学推导，不是下载文件大小；实际整数像素维度、压缩元数据、封装、overlap重复窗口应在配置中单独核算。

仅按3:1缩小传输字节并不能表示已经实现了压缩与解码。若真实图像实验仍使用RGB检测模型与本机CPU/MPS代理时间，需要明确原生PAN/MS到模型输入的预处理尚未实测，不能把这些代理时间称为星载硬件性能。解码、融合、辐射校正、压缩质量对精度的影响也不能自动视为零。

原图整幅下传与分片卸载应使用同一压缩口径；分片模式要计入实际重复像素，不能以“整图只压缩一次、分片全部不压缩”的不对称设定人为放大某种方案收益。只有结果输出无需传完整像素时，才使用任务实际输出格式对应的字节账本。

## 5. 实验结论的表述边界

可表述为“基于公开在轨任务及终端规格的网络层仿真，星间10 Gbps、星地双通道聚合1.2 Gbps，另设协议效率敏感性”。不能表述为“真实星座实测带宽”“真实链路吞吐已标定”或“真实硬件上证明强化学习优于其他方案”。

把真实通信速率引入后，整图下传可能只占一个过境窗口的一小部分；主要瓶颈可能转向首次接触等待、成像突发、计算队列和地面接入竞争。即使地面方案因此更强，也应保留并解释结果，不能为获得预定胜负而降低带宽。
