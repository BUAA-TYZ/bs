# 混合计算中的原始输入地面中继：接口设计

状态：2026-10-15 已实现并通过执行器、资源核算和公共规划器回归，实验结论见[研究记录](experiment_log.md)。本文保留设计理由；最终实现不允许规划器承诺非同时连通的未来ISL路径。动机是统一分布式方法与纯地面中继的执行能力，避免仅纯地面基线能把原始分片经多颗卫星送到地面。

## 1. 公共动作与状态

- 配置 `ground_input_relay: bool = False`，默认关闭以保留旧实验。星上计算目的地仍受 `input_relay_max_hops` 限制；地面原始输入的中继上限沿用 `relay_max_hops`，其含义为星间跳数，报价中还需加最后一个星地跳。
- `Action.relay_to_ground: bool = False`。开启时必须同时满足 `OFFLOAD`、有效 `target_gs_id`、无 `target_sat_id`、空 `input_path`、配置允许且分片尚未被承诺。动作指定最终地面站，而不是指定逐跳路径。
- `Tile.ground_relay_target: str | None` 固定接单目的地。接单后进入不可再次调度的原始数据中继状态；未来窗口暂不可用时保留源数据等待，不将其视作错误或送入星上 CPU。
- 自动执行器在每跳重新调用公共路由，按真实剩余字节传输，完整到达后才启动下一跳。保留访问历史和剩余跳数；路径中断时采用现有等待/失败配置。
- `delivery_route` 增加可选 `target_gs_id=None`，仅过滤最终地面站，默认值保持原纯地面中继与结果中继行为。不能先选择任意地面站再仅在动作阶段替换目标，这会改变最早路径计算。

接纳地面任务不要求有立即可发的首跳；能够基于公开窗口作出承诺，再由执行器等待。该规则意味着地面队列广播从接纳时开始承担承诺，而不是直到最后一跳到地面才记账。

## 2. 公共输入报价

保留现有返回类型 `processor -> (arrival_seconds, path_contact_indices)`，地面节点仍表示为 `("ground", gs_id)`。建议新增 `ground_input_options(state, plan, tile, memory)`，由 `current_input_options` 在配置开启时合并；地面报价不依赖卫星 VRAM 可否容纳推理任务。

地面报价对每个 GS 使用相同公开接触图搜索，终点集合只含该 GS，上限为 `relay_max_hops + 1`；所有ISL必须当前连通，允许等待未来地面窗口。它不读取未来任务、未来排队或环境私有轨迹。星上路径继续使用当前接触、每跳公共邻居候选与两跳上限。本面板拓扑度上限为4；公共候选 API 的通用上限为8，两者并不冲突。

`ContactPlan.delivery` 现有容量过滤检查整片是否能通过，但其 `arrival` 不会把已经扣减的容量转换为当前排队等待。直接用它作地面原始大分片报价，会出现“剩余总容量足够就仍按空队列时间到达”的偏乐观估计。因此至少应满足以下两点：

1. 每条候选路径逐跳按公开积压和同轮预留字节复核到达时间；在一个窗口内累计字节后量化，不能让每个小包独占一个时间步。
2. 路径报价及其索引来自同一个剩余 `ContactPlan`；所有原始输入跳扣减完整 `tile.data_size_mb`，地面计算后不再对同一原始输入额外收取结果下传费用。

对于未来接触，等待到 `contact.start`，但排队服务不能发生在接触开始以前。对于中间节点，完整接收才允许下一跳发送；检查完整数据到达各接触结束前，而不是仅检查首字节到达。

若需要与真实路由更一致，可以给现有 `execution_delivery` 增加可选 `destinations` 和规划内存账本；所有方法共用这一模式。当前它只能选任意地面站，且只读取 `state` 中缓存，不能直接作为固定目标、同轮缓存扣减后的报价。接触图模式与执行器重放模式必须预先固定并统一给所有方法，不允许仅给新算法使用更准的原始输入报价。

动态执行路径可能与报价路径不同。接触总量预留是本轮规划近似，不是跨轮带宽保证，更不是 MSR 固定路径执行；实验应如实标注。

## 3. 内存与计算承诺

原始地面中继没有最终卫星 CPU，也没有最终卫星的永久输入缓存预约。实际执行只持有源/当前位置与正在传输下一跳的缓存；每跳结束释放前一跳缓存。规划时可以用所有预计中间节点的当前缓存做保守可行性检查，但不能把这种检查说成执行器已经预留未来缓存。

建议扩展 `reserve_input_memory`，按终点类型区分：星上固定路径保留当前保守的所有远端节点扣减；地面动态路径只按已经确定的立即首跳扣一次同轮缓存，未来路径不预扣全部节点。若选择对整个预测路径保守扣减，也必须对所有方法统一并记录其与实际缓存生命周期的差异。最终 GS 不在卫星内存账本中。

`env.export_state` 的计算承诺需先判断 `ground_relay_target`：接纳后到完成前只计入固定 GS，绝不能由于存在原始 ISL `Transfer` 而计入下一跳卫星。地面目标的承诺集合应按分片 ID 去重，包含源上等待、ISL在途、下传、地面排队和运行中分片；完成或失败后移除。运行中的分片计剩余计算量，其他阶段计完整未执行计算量。

## 4. 调度方法接入点

| 组件 | 最小适配 |
| --- | --- |
| `action_for` | 增加明确的配置参数，例如 `state=None` 或 `ground_relay=False`；选择 GS 且能力开启时构造 `relay_to_ground=True`，不填卫星 `input_path` |
| CGS | 通过公共报价获取 GS 候选；允许非当前可见 GS 接单，不能仍走旧的 `WAIT ground_window`；预留原始输入路径后地面计算即可完成 |
| HEFT | 静态排名保留初始边权，放入日历前复核选定输入路径的剩余容量和未来窗口；地面输入路径不能再受卫星两跳限制 |
| DTS | 使用同一地面候选并采用既有“输入传输 + 已承诺队列 + 服务”加和规则；这已扩大原 SEN 范围，需明确标为 hybrid adaptation |
| Rolling | 地面未来路径代表“现在接受地面中继承诺”，不能误用未来星上候选的第三字段将其转成 `WAIT` |
| TaskQuota | 配额仍按最终 GS 计数，实际派发阶段也使用公共地面报价重新校验，不能退回当前直达可见性过滤 |

DTS 当前排序元组包含处理器 ID。加入 tuple 型 GS 后，相同估计响应与相同本地标志可能导致 Python 比较 int 与 tuple，需采用明确稳定的同类排序键。各方法应保持相同候选和成本口径；不能为了加入地面候选而修改原先的策略目标。

## 5. 实施后必须覆盖的验收用例

1. 默认关闭时旧的一跳、两跳星上路径和纯地面基线动作与结果不变。
2. 源星看不到 GS，中继星能看到时，CGS、HEFT、DTS hybrid、Rolling 与 TaskQuota 都有同一个固定 GS 候选。
3. 无卫星可容纳推理 VRAM 时，原始数据仍能中继到有能力计算的 GS；中继节点不运行推理。
4. 地面目标在接纳后到原始输入到达前就出现计算承诺；源上等待、ISL在途和下传过程不计入卫星 CPU。
5. 两个 GS 的到达时间交叉变化时，已接纳目标不被公共自动路由悄悄切换；默认纯地面基线仍可自主选择 GS。
6. 当前ISL连通且只有未来星地窗口时可接单等待；只有未来ISL首跳或非同时连通时序路径则不报价。真实执行器不支持后一种时序路径，因此不能把它当可执行承诺。
7. 每个输入跳都扣完整分片体积；同向多个原始分片与已有传输共享真实字节容量，不因为增加路径而复制带宽。
8. 中间缓存不足时不能开始该跳，等待后恢复；首跳发送失败不留下虚假地面承诺或泄漏缓存。
9. 分片在每跳结束后的下一步才可再次发送；中继历史防环且星间跳数不超过 `relay_max_hops`。
10. 已承诺地面分片不能再被普通 `LOCAL/OFFLOAD` 改派或重复接单；全部中间阶段从公共可调度候选中排除。
11. 到达地面后承诺不重复计入下传与队列；实际计算开始时只剩一次工作量，最终完成/失败释放全部状态。
12. 硬期限失败沿用原取消机制；300秒软 SLA 不变成隐性丢弃。最终图像统计继续要求全部原始/结果分片对应计算完成。
13. 对至少两幅图验证同轮 GS 排队更新与路径剩余容量更新，后续决策不能反复使用第一个分片的空负载报价。
14. 预测路径和实际动态路径分别记录，不能把报价路径当成实际完成轨迹。对星上和地面选择保持输入体积、重叠和最终后处理规则不变。

完成公共能力后重新冻结核心，用未参与选参的日期检验。这个能力修正仅消除比较中的动作范围差异，不构成本文调度算法本身的性能结论。
