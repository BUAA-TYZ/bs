# 高分遥感候选星座几何审计

核查日期：2026-10-15。本次独立审计固定源星轨道和同一批成像事件，只比较两种计算中继层布局。使用仓库现有轨道、成像和终端匹配函数，不修改调度策略，不根据算法胜负调整轨道。

结论：将全部24颗星集中在两条相近太阳同步轨道面，会在美国成像后形成整个星座对北京站长达数小时的共同接收空白。保留两颗成像星、把22颗辅助星放到独立中倾角轨道，能够显著改变接收机会。这属于**体系结构对照**，不构成任何调度算法优越性的证据。

## 1. 共同条件与方法

| 项目 | 本次核查条件 |
| --- | --- |
| 历元及到达区间 | `2026-10-15T00:00:00Z`，UTC自然日 `[0,86400)`；不是北京时间10月15日零点开始 |
| 轨道传播 | 现有 `walker_tle` 生成合成TLE，SGP4/WGS72传播，Skyfield/WGS84地面几何 |
| 成像源星 | 620 km、97.9度，两个RAAN分别357.5/12.5度，初始相位0/15度 |
| 观测区域 | `sim/acquisition.py` 的5个美国民用农业、植被圆形研究区域 |
| 成像约束 | 离轴角不超过30度，地表太阳几何高度不低于20+1度，地面仰角为正 |
| 成像扫描 | 10秒扫描，输出与1秒仿真步对齐；每源星/区域连续窗口最多3条带，源星全部区域共享30秒间隔，同源同区域窗口首条带相隔至少600秒 |
| 星间几何 | 地球遮挡，地球半径6371 km，最大距离4500 km，不额外设星间仰角限制；按距离贪心匹配，双方最大degree为4 |
| 连通性采样 | UTC自然日每10秒采样，共8640个时刻；未进一步假设通信建链成功 |
| 地面站 | 北京城市参考点39.9042 N、116.4074 E、高程50 m，最低仰角15度；不是实测站址 |
| 交付机会诊断 | 从每个事件向后4小时搜索接触；原双SSO方案另延长到48小时找实际首次接触 |
| 速率 | 10 Gbps星间、1.2 Gbps下行及eta敏感性不改变本次纯几何统计；本次没有跑计算或业务流量 |

脚本通过现有函数在内存中构造以下两组TLE。卫星标识以列表索引为准，原辅助函数独立调用可能产生相同目录编号；本审计没有把目录编号当作唯一节点ID。

```python
epoch = "2026-10-15T00:00:00Z"
plane_a = walker_tle(epoch, 1, 12, 620, 97.9, 357.5, 0, 0)
plane_b = walker_tle(epoch, 1, 12, 620, 97.9, 12.5, 15, 0)
coorbital_tles = plane_a + plane_b
coorbital_sources = [0, 12]

independent_tles = [plane_a[0], plane_b[0]] + walker_tle(
    epoch, 2, 11, 550, 53, raan_offset_deg=0,
    phasing=1, plane_raan_offsets_deg=[0, 90],
)
independent_sources = [0, 1]
```

对每一时刻先计算全部276个无向星对的几何可见性，再调用 `bounded_edges(..., max_neighbors=4)`，最后遍历图的连通分量。地面接触使用 `(satellite-ground_station).at(times).altaz()` 的仰角。下表的边寿命是同一对卫星被实际选入匹配图的连续时段，排除在审计区间边界被截断的时段；它可能因终端匹配变化而结束，未必是地球遮挡。

## 3. 两条相近SSO轨道面的负结果

该布局为每面12星，共2颗源星和22颗辅助星，所有星同高、同倾角。全天8640个采样时刻均为单个24星连通分量，始终48条边，每颗星degree均为4，**没有一次边集合变化**。源0邻居固定为 `[1,11,12,23]`，源12固定为 `[0,1,13,23]`；每源均有3颗专用计算邻星和另一颗源星。图直径为6跳。

21个成像事件之后的4小时内，源星本身、当时邻星乃至整个24星连通分量均无北京站接触。只要仍以地面完整交付为完成，所有算法的4小时内完成率在该日都会是0；这是几何上不可能，不是训练不足。

全天最后一段成像前的全星座接收机会在10月15日16:11:10 UTC结束。成像后第一次全星座可接收机会为**10月16日01:51:00 UTC**，由节点5提供，采样窗口170秒；从两个源到该节点的静态最短路径均为5跳。对本批事件，最早任何节点可下传的等待范围为7小时23分30秒至9小时6分。

## 5. 物理适用范围与剩余验证

550 km、53度作为通信服务层有真实公开轨道参数量级参照。Starlink提交Ofcom的[技术附件第5页表A-2](https://www.ofcom.org.uk/siteassets/resources/documents/consultations/category-3-4-weeks/281181-kepler-communications-inc-application/associated-documents/starlink-annex.pdf?v=393905)列出该高度和倾角。此引用只支持轨道量级；它不证明本研究2面×11星、RAAN相差90度、4终端的稀疏布局等同于Starlink，亦不证明其全年接收性能。

53度轨道可覆盖美国大陆研究区域和北京所在纬度，620/550 km不同高度也允许按几何条件建立跨轨链路。但以下限制必须保留：

1. **高相对角速度没有终端级验证。** 全日10秒扫描最小星间距离77.729 km，对应源1与辅助11；在其邻近时段改用1秒扫描，10月15日23:29:57 UTC距离为75.269 km、相对速度6.140 km/s、视线角速度约4.673度/秒。这里由 `norm(cross(relative_position,relative_velocity))/range**2` 推算角速度，未加入平台姿态补偿。现有SCOT80证据没有给出可据以验收这一工况的最大跟踪角速度，因此几何可见不保证真实终端可以建链并保持10 Gbps。这些距离也不构成碰撞安全验证。
2. **短暂边可能不能被实际利用。** 10秒寿命的匹配边可能受重新捕获、指向切换或终端调度开销影响。当前匹配按距离瞬时变化，没有建链滞回和指向惯性；不能称为实际光学终端控制协议。
3. **相对轨道面会随日期改变。** 使用WGS72常数的一阶J2公式估算，源星节点进动约+0.9898度/日，计算星约-4.4892度/日，相对RAAN每天约改变5.479度。SGP4会传播这些变化；10月15日的事件接入表现不能推广为全年不变，应使用独立日期和初始相位验证。
4. **采样边界有限。** 本审计10秒采样，正常解析到的可见窗口边界具有步长级误差，短于采样间隔的窗口可能漏掉。21个任务的成像角度约束只针对中心代理点，不保证整幅条带曝光过程满足同一约束。
5. **这仍是几何可行性核查。** 未将推理服务时间、全图完成条件、有限缓存、接收站竞争、协议开销或任务调度加入该表。先冻结架构并保留两种布局结果，再在同一架构内部比较算法，不能把跨架构变化解释为MARL收益。
