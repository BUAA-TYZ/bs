# 整图滚动接纳实验

更新：2026-10-10。此文记录预约退化审计及其针对性修正；既有八场景是开发面板，不是独立测试集。

## 已复现的退化原因

`analysis/audit_reservation_regression.py` 重放 uniform12_a/b 的预约与无预约策略，保存动作和分片生命周期。四次运行逐任务结果均与上一轮归档一致，原始证据在 `results/relay_reservation_regression_20261010/`。

| 场景 / 任务 | 原预约中的尾分片路径 | 无预约整图时延 | 原预约整图时延 |
|---|---|---:|---:|
| uniform12_a / task_14 | tile_0 在 4560 秒进入低算力源星 0；9040 秒才开始计算，9630 秒计算完 | 1100 秒 | 5120 秒 |
| uniform12_b / task_19 | tile_0 在 4530 秒从源星 9 发向低算力星 0；9240 秒开始计算，9830 秒计算完 | 1130 秒 | 5350 秒 |

其余兄弟分片随后获得更快计算路径，但先前接入慢节点的分片已承诺执行。接单时单片看似可行，不代表此时接入对完整图像有利。事件时间是步起点；最终完成与任务时延以 `task_outcomes` 为准。

## 本轮实现

新增 `reservation_joint_sequential` 和 `reservation_joint`。两者均先尝试为同一图像全部尚未分配的分片安排计算与回传；任何一片找不到可行安排时，丢弃本次试排，本轮可见分片一起等待。搜索成功后，只提交公共接口允许的每星每轮最多四个动作。

`EnvState.pending_task_tiles` 保留已产生的同图未分配分片元数据；没有读取未来到达任务。超出当前四个候选的分片使用源星队列位置估算最早可派发时刻。成功计划中的虚拟后续分片也占本轮规划容量，下一轮则从真实执行状态重建账本。

顺序版只保留一个部分方案；搜索版固定保留四个，以预计最晚分片交付时刻为第一目标、分片交付时刻总和为第二目标。每个执行目的地仅保留当前最早回传报价，以限制开销。宽度在此次面板运行前固定，没有按场景切换。

这仍不是跨轮原子事务：先前已接单的分片不能撤销，后续四片也不保证执行上一轮试排。预测只覆盖当前星间接触、最近星地窗口和至多一跳结果中继；完全看不到预测窗口时仍沿用原策略的 greedy 回退。有限宽度搜索失败表示没有找到方案，不构成数学不可行性证明。共享账本和无信令成本等边界延续上一版。

## 验证协议

新增四项测试，覆盖不完整整图的拒绝及试排回滚、多目的地分流和 READY 兼容、隐藏兄弟分片与四动作限制、环境导出完整未分配分片。全套 116 项测试通过。

```bash
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python analysis/evaluate_reservation.py --workers 3 \
  --policies greedy reservation reservation_joint_sequential reservation_joint \
  --out-dir results/relay_joint_reservation_reproduced
```

运行八个既有开发案例，每种方法完整六小时；到达、轨道、物理规则、候选数量和结果中继一致。结果目录 `results/relay_joint_reservation_20261010/`。主评分为 30/60/120/240 分钟交付率等权平均，辅助指标为四小时限制平均时延；保留所有任务作为分母。

## 初步诊断

整图预检将上述 task_14 时延从 5120 秒降到 1100 秒，将 task_19 从 5350 秒降到 260 秒。不过 uniform12_a 的 task_20 同时从 1100 秒退化到 3630 秒，uniform12_b 的 task_25 从 710 秒退化到 3210 秒。故尾分片案例改善不能代替整体有效性检验。

对两个新退化案例又重放完整动作、生命周期与接单报价，逐任务结果与评估一致。文件为 `results/relay_joint_reservation_audit_20261010/`，报价重现脚本为 `analysis/audit_joint_quotes.py`。

- uniform12_a / task_20：6100 秒时，源星 6 将 tile_6 送到慢星 0；当时已知该星承诺计算量 2940 秒，新片还需 600 秒。搜索预计它约 3550 秒后抵达地面，而另一个快星 5 的晚分片被估计需要约 4510 秒才可直传。因此有限回传估计允许这个慢分片成为次优目标中的选择。实际公共多跳路由使全送星 5 的旧策略整图只需 1100 秒，新策略却等慢星至 9630 秒计算完。本例不是单纯的队列漏计，而是低估多跳回传机会、错误比较计算目的地。
- uniform12_b / task_25：6610 秒时，3→8 链路报价为 11.6253 Mbps，预测剩余接触 50 秒，三片串行预计约 32.9 秒传完。随后两个快照带宽降为 6.3754、6.2485 Mbps，6640 秒链路已断，早于预测末端 20 秒。原始分片直到 9070 秒才收到。30 秒扫描的窗口边界误差与固定当前带宽估计叠加，让纸面可行的接单失败；整图预检无法独自修复这种误差。

这给出下一步可验证的方向：原始数据接单要纳入接触边界的不确定区间与带宽保守估计，回传报价需覆盖多段未来接触。前者必须做不同扫描精度和带宽波动下的消融，后者应对齐共同实际路由的信息权限。不能通过取消带宽竞争、删除退化任务或按案例切换策略来获得提升。

32 次轨迹全部完成，三个工作进程墙钟约 354 秒，源码指纹为 `1ac509f9db971706f68fa11b61f9096f6effa3f0ce8b2d5998352b496958cccf`。同场景各方法的任务、轨道、配置和源码指纹一致，greedy 与原预约共 16 次运行逐任务结果与上一轮归档完全相同。

相对原预约，整图搜索的评分增加 0.1498 个百分点，限制平均时延减少 45.3279 秒；五场景评分升、两场景降、一场景不变。完整交付集合相同，共同完成任务中 64 个更快、83 个更慢、606 个相同。不能将较少的加速任务数或平均改善解读为逐任务改善。uniform12_a 的平均时延改善而评分下降，反映四个固定时限与连续时延的不同统计含义，主指标不能事后更换。

四候选搜索相对顺序版没有评分或完成率增益，限制平均时延仅低约 0.0367 秒。此结果不支持增加搜索复杂度作为主要优化方向。两版整图预检保留为实验候选，原逐片预约也保留，不按开发案例名称切换策略。

对 greedy 的整体评分差为 +5.2186 个百分点，但不能全部归因于本轮整图预检，更不能归为强化学习收益。当前结论是整图预检有小幅开发收益且存在明确退化，尚无泛化或统计显著性结论。本轮没有消耗新的最终测试集，也未完成文献方法复现；先修正已定位的预测误差，再冻结方法与新的独立评估协议。
