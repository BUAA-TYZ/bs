## 三、下一步怎样判断是否值得继续训练

2026-10-10 更新：原场景步骤 1、2 已完成，见 [协同收益诊断](cooperation_feasibility.md)。按新的任务交付目标，结果中继现已扩展并完成机制开发验证，见 [结果中继验证](result_relay.md)。接下来完善地面控制、路由诊断、信息权限与任务年龄训练协议，再进行学习诊断。以下保留决策依赖供后续追踪。

1. **先做可执行小案例。** 让同一任务在 local 下无法完整交付，而一条合法的原始分片卸载路径能完成，记录每段传输、计算与交付时间。允许用小规模枚举或有明确未来信息权限的离线规划验证机会，但必须标为诊断参考，不当作同信息在线基线。
2. **再分解当前瓶颈。** 使用生命周期与完成时间统计计算等待、计算服务、计算后等待和传输时间。当前审计说明 728 个分片都已计算，448 个尚未交付；应优先检查交付机会与卸载代价。
3. **据证据处理模型边界。** 若核心收益来自计算负载平衡，继续原始分片卸载问题；若来自小结果经邻星中继，明确是否扩展问题，并对所有策略统一实现。此选择先由小案例和业务范围确定，不根据预留测试成绩挑选。
4. **最后诊断学习。** 在已确认存在收益的开发案例上检查可行动作、探索概率、训练奖励、价值误差、随机/确定性策略差异以及候选截断是否隐藏有利分片，再增加训练预算。

不以“卸载越多越好”作为奖励，不删除 local 对照，不因候选没有领先而不断查看和重选测试集。结果需要允许研究假设被否定。

## 四、正式实验最小矩阵

| 类别 | 方法或变量 | 要回答的问题 |
|---|---|---|
| 应用主对照 | ground_compute；补充仅地面计算的分片流水线控制 | 相对全地面处理是否更快；收益是否仅来自处理流水线差异 |
| 简单但必要的对照 | local、greedy、window_aware | 是否超过无需学习的强策略 |
| 通用学习基线 | IPPO、MAPPO | 多智能体集中训练是否有价值 |
| 领域方法 | 经核验的论文方法；现有 Co-MAPPO learning-component (adapted) 保留完整名称 | 与已有卫星研究相比有什么差别 |
| 输入与结构控制 | 增强输入 MLP、候选注意力 | 效果来自信息还是结构 |
| 核心消融 | 去任务信息、去预测窗口信息 | 两项设计是否必要 |
| 可选训练消融 | 势函数系数为 0 / 非零 | 是否改善学习，是否值得保留 |
| 条件变化 | 负载、带宽、窗口/站端通道、计算压力 | 哪些条件有效，哪些无效 |

正式多重复拟用训练种子 7、107、207、307、407。历史随机星座协议为 `examples/scenario_distribution.json`；当前角色协议为 `examples/scenario_roles.json`，验证种子 81001--81008，本轮独立测试 91001--91006。该测试用于固定候选的一次评估，后续方法开发需要另留新的未查看面板，不能反复据此调参。训练回合另按训练种子派生任务随机种子；扩大预算或多重复前须核对种子范围，必要时改为显式不重叠方案。先冻结任务与轨道划分，再进入正式测试，不能机械规定轮数就算充分。

当前主指标为任务年龄 30/60/120/240 分钟交付率的等权均值，再对场景等权平均；同时报告完整任务合计交付数。次指标为四小时限制平均时延，并补共同完成任务上的配对时延。同步报告失败/未完成比例、实际卸载、协同交付比例及训练和推理成本。不能用仿真结束时的完成数替代年龄评分，也不用仅成功样本的低时延掩盖低完成率。

## 六、中期与最终论文的边界

中期建议达到：问题与模型固定；方法完整可复述；领域基线有可信实现和公平协议；主对比与核心消融至少有一套能够解释的多重复结果；六章正文和引用齐全，局限明确。是否必须在中期前完成全部泛化实验，由学院要求与导师安排决定。

送审前需要进一步冻结代码与数据、补齐稳健性、检查结论适用范围、统一格式引用，并让关键主表可独立复算。若方法未稳定超过 local 或同输入 MLP，就应调整方法或收窄结论；不能将系统实现包装为已证明的 MARL 算法优势。

目前最短路径为：**协同机会验证（已完成） → 场景与方法边界固定 → 强基线及训练诊断 → 主实验 → 核心消融 → 替换论文实验与结论 → 模板整理和导师修订**。相关工作、参数来源和正文可并行推进，但正式测试必须排在协议冻结之后。
