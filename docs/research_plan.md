# 星间通信约束下的多智能体协同调度研究计划

目标修订日期：2026-10-09；下文实现回顾主要保留 2026-09-30 的阶段状态，后续进展见末尾链接。最新目标以 [研究目标与建模约定](thesis/research_scope.md) 为准。本文区分已实现基线、研究假设和待复现方法；不将候选设计描述为已验证创新。

## 1. 已确认的研究边界

- 面向论文/毕业设计，先完成仿真，不做真实卫星、开发板或容器图像执行原型。
- 强化学习、多 agent 是核心方法方向；每颗卫星作为 agent。
- 保留开题题目“面向遥感图像处理的多星协同任务调度技术研究”。distributed 允许本星计算、邻星卸载和地面计算；ground_compute 为必需主对照。
- 核心应用目标是在保持完整 task 完成率的前提下，相对全部地面计算缩短完整图像的端到端交付时延。所有 tile 结果汇聚并完成聚合才算任务完成；当前不同地面站间汇聚和聚合为隐含零开销，需补模型与敏感性分析。
- 原开题三点收敛为：通信约束建模、窗口与任务状态感知的 MARL、可复现仿真验证。
- 不声称首次实现星座协同计算，不在无功耗模型时声称能源效率提升。

## 2. 当前已落地的基线

模型 v2.0 修正了步号被当作轨道秒数、并发传输独占完整带宽、资源重复释放、完成延迟单位等问题。星间链路按方向独立容量；同向传输采用流体公平分配。每个地面站默认 1 个接收通道，每通道 20 Mbps，接入卫星按步轮转；每颗卫星同一步最多接入一个站。多接收通道按每通道带宽扩容。

已提供 greedy、load_aware、window_aware、random、参数共享 IPPO，以及具有集中式 critic 的 MAPPO 基线。所有策略每星每步最多决策 4 个相同规则选出的 tile；硬资源冲突仍在环境中处理。单个动作的 mask 只反映当前可行性，不保证多个 agent 同时请求同一目标时都成功。

IPPO 和 MAPPO 共用局部 actor 输入、动作空间和奖励。MAPPO 的 critic 输入是全体卫星观测拼接加当前卫星观测，推理不使用全局信息。它是本仓库的 MAPPO 风格实现，不是作者官方代码或论文完整复现；尚未加入 value normalization、循环网络等可选组件。

训练修正包括：按 `[time, agent]` 计算 GAE、逐 agent bootstrap、处理末尾不足 rollout 的数据、终止 mask、动作可行性 mask、训练和验证种子分离。仿真时长视为有限时域目标，终点不 bootstrap；仍未完成的任务保留为 pending，不自动算失败。`best.pt` 按验证集 task 完成率和已完成 task 平均时延选择。完整配置、种子和模型语义版本保存到 run.json 和 checkpoint。

已知仍需研究的问题：默认奖励仍为 tile +1、task +10、失败 -2、QUEUED/READY 等待 -0.01/step；它不等价于严格的 task 完成率目标，且传输/等待下传状态不受等待惩罚。候选 tile 的 task 摘要来自仿真器全局真实状态，现实分布式实现需建模反馈消息的时延、带宽与一致性。不能把当前无成本信息访问当作已解决的工程问题。

## 4. 候选核心方法：窗口预测与完整任务协作

研究假设：在计算、通信和结果交付相互制约时，逐 tile 的局部最早完成决策可能无法最优地完成整个 task。学习策略有机会利用剩余窗口容量与任务完成进度，协调位置分配和等待选择。收益必须在测试集上验证，也允许观察到无收益或退化。

建议以 MAPPO 为候选骨架，分阶段验证以下设计，暂不命名为新算法：

1. 窗口状态：当前/下一窗口开始时间、剩余时长、共享容量估计与待传字节；增加 ISL 窗口预测，当前只有星地窗口预测。窗口容量用于评估机会成本，不强制完整 tile 必须在单次窗口内传完，因为模型允许续传。
2. 任务状态：已完成、失败、剩余 tile 比例，以及各剩余 tile 预计交付时间的摘要。避免把“集中在同一卫星”直接当成好策略，任务完成取决于最晚交付时间。区分仿真真值与 agent 可获取的信息。
3. 协作机制：基于任务关系的邻居/任务编码，与纯 MLP MAPPO 在相同输入信息和预算下对比；优先证明任务关系有价值，再决定是否需要注意力或图网络。
4. 奖励：评估 task 完成主奖励加任务进展 shaping。候选势函数例如未失败任务已交付比例的有界凸函数；使用 `gamma * Phi(s_next) - Phi(s)` 并处理终止状态。权重只在验证集选择，消融中区分奖励改变与网络改变。
5. 恢复：将长时间断链后的继续等待与取消卸载后重新选目标作为动作候选，计入已传字节浪费和重新传输成本。这里是任务重新分配，不是运行中执行状态迁移；当前实现仅暂停续传/直接失败。

优先实现窗口和任务状态，再实现一个明确的协作机制。优先级、deadline 可以作为后续场景；阳照、功耗和真正状态迁移暂不进入主线。

## 5. 实验协议

- 主表：ground_compute、local、greedy、window_aware、IPPO、MAPPO、至少一个完成核查的卫星领域文献方法、我们的方法。ground_compute 是固定处理模式，不能声称它接受了不同调度策略；另需控制分片流水线带来的收益。
- 公平性：相同 TLE、任务轨迹、通信容量、候选 tile 数、调度频率；明确各方法的信息权限。所有学习策略使用相同环境交互预算和可比调参预算，不只比较 episode 数。
- 数据划分：训练/验证/测试种子不重叠；轨道起始时刻、负载和星座规模另设未见测试场景。仅改变到达随机种子不构成轨道泛化。
- 重复：正式结论至少 5 个独立训练种子、每个 checkpoint 多个配对测试场景。按训练重复和测试场景分层估计不确定性，不能把同一轨迹上的每个 tile 当成独立重复。
- 指标：完整任务完成率、失败/pending 数、已完成任务时延 mean/P95、tile 完成率、链路利用率、资源占用、单步决策时间。时延是完成条件下统计，不单独用于排名。
- 时域：明确截止时刻后是否停止产生任务并排空队列。当前为固定时域、无排空；任务到达越晚可用时间越短，不能将 pending 全部解释为调度失败。
- 敏感性：负载、20 Mbps 基准附近的带宽、接收通道 1/2/4、星数、tile 数、`dt` 时间分辨率。调整 `dt` 时保持单位秒的任务到达强度和物理截止期一致。
- 消融：无预测、无任务级状态、无协作编码、无进展奖励、无恢复动作；分别记录输入权限与动作能力变化。
- 实现正确性测试是所有方法的共同前提；action mask、单位修复、GAE 修复本身不作为论文创新。
