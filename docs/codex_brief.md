## 1. 总体研究思路

不追求“通用地超过所有文献方法”。思路是：**找到最强基线在哪里失败、为什么失败，只针对这个失败机制设计组件，并证明组件带来的增益。**

方法形态优先为“最强基线（CGS 或 HEFT 适配） + 一个明确组件”，用 CGS vs CGS+X 做干净消融。MARL 不是必须项，见第 3 节 T5。

## 3. 任务顺序

### T1 测提升空间上界（≤2 天）—— 最先做

- 当前状态：已完成改善空间判定，触发 <5 个百分点的停止条件。用户随后要求重新考虑场景与CGS+X，当前进行候选设计核查，没有启动额外压力实验或训练。
- 目的：判断当前 CGS 的 89.6732% 距离可达上界还有多远，决定后续是否值得在本场景设计方法。
- 做法：在小实例（如 day01 或某时间段子集）上，用拥有完整未来信息的离线规划（MILP / CP-SAT / 小规模枚举，可松弛）求 P_300 上界；同时给出每个任务的物理可交付性（零计算、无限星间带宽时是否可能 300 秒内到地面）。
- 交付：每日一张表：物理上界 / 离线规划上界 / CGS / greedy。离线规划明确标注“使用未来信息，仅作诊断参考，非在线基线”。
- 判定：若 CGS 已接近离线上界（差距 < 5 个百分点），停下来汇报，说明本场景改进空间有限，等人决定是否调整负载条件（见 T4）。
